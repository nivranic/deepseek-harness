# Agent Note: 独立原生 Desktop 更新管理器

Status: proposed

[English](2026-10-28-native-desktop-update-manager.md) | 中文

## Problem

个人 fork 需要可重复执行的 Windows 构建及本地部署入口，同时保留现有应用、用户数据和无关开发工作。构建完成、安装验证及快捷方式维护是不同结果，单个成功字段无法安全恢复中断更新。

## Proposal

管理器使用独立 C# 解决方案，包含 WinUI 3 界面、共享核心和 CLI。保存结构化持久阶段、完整产物身份、固定远端 SHA 以及独立部署验证。调用 fork 的无签名 NSIS 流程与隔离运行时冒烟测试，使用有归属标记的专用源码工作区和项目支持的安装目录参数。

管理器从包含 .NET 与 Windows App SDK 的完整自包含目录运行。Windows Job Objects 仅拥有任务子进程。现有目录必须核实归属并拒绝重解析点；管理器替换先完整暂存与验证，再使用同卷 Directory.Move 晋升，保留旧目录用于恢复。

配置保存与更新任务持有同一个跨进程锁。已打开实例在持锁后核对已保存的构建配置，再调用后端。安装验证使用预期产物的完整文件清单；相同版本和提交的旧收据不能证明重建包已经安装。待完成部署收据只有在该验证通过后才晋升为已提交收据。

子进程的每条输出管道分别维护跨有界字节分片的凭据脱敏状态。显式 secret 掩码只控制输出，原始字符继续驱动凭据语法识别；保留的 UTF-16 文本不拆开代理对。长凭据值直接丢弃，不缓存完整行；磁盘日志与有界界面展示接收同一份脱敏输出。

启动诊断使用显式启用的有界 QPC 时间戳与固定阶段名，不含配置值或日志内容。诊断在正常关闭并通过受管目录检查后写入，不改变任务状态。日志控件首次展开时创建，随后保留搜索和跟随状态；收起展示不停止日志落盘及有界缓冲。UI Automation 调用耗时包含 provider 工作及等待界面线程，不能从启动样本中直接扣除以证明用户可交互时间。

## Alternatives considered

**Electron 管理界面。** 复用目标应用的渲染器会把更新器与需要替换的应用耦合，并增加独立 JavaScript 界面运行时。按需求采用 WinUI 界面，将更新执行统一放在可复用 C# 核心。

**只复制应用 EXE。** 应用需要完整 Electron 资源、运行时与安装注册。fork 支持的 NSIS 流程负责这些安装行为及目录回退。

**同步当前开发工作区。** 专用受管工作区可以固定单个提交，同时保留未提交修改以及用户的分支和远端配置。

## Acceptance criteria

完整管理器从指定 BAT 启动，在联网前显示本地信息，并展示结构化任务事件。行为测试覆盖 SemVer、最终落盘失败、进程归属、取消、产物复用及异常路径；原生界面、真实完整构建安装、启动与性能分别验收。

真实应用打包需要获准的 Mandatory Update 服务 origin。地址格式合法或 fixture 测试通过不能满足这一外部依赖。实际测量结果与剩余事项见[管理器验证记录](../../../../desktop-manager/docs/verification.zh.md)。

## Risks

自包含交付增加磁盘占用，并需要维护两套运行时发行内容。同卷目录重命名保留可恢复备份，但不是断电场景下的一次原子交换。程序文件回退不能证明迁移后的用户数据兼容。fork 没有默认生产更新服务 host，必须先核实服务后才能验收真实打包。
