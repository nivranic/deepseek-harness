# Agent Note: The companion support document collects the Host runtime-health snapshot

Status: implemented

English | [中文](2026-10-27-host-runtime-health.zh.md)

## Problem

The Android companion's support export listed `"runtime-health"` in its `uncollected` array permanently — the string was hardcoded beside `"updates"`, so the document never carried any Host §41 health or readiness fact, paired or not. The Kotlin side held no Host-health projection at all (a repository-wide search confirmed zero references), and no shared diagnostics vocabulary crossed the wire: the Host already serves `hostDiagnostics/health` (six components plus the derived readiness verdict) and advertises `host.diagnostics.v1`, but the companion neither recognized the capability nor called the endpoint. The §41-44 family row also carried a stale half-sentence: consent-classified telemetry-off-by-default has been the shipped baseline for a long time (four consent categories all `default(false)`), yet the family row still named it outstanding.

## Decision

The support document now embeds the Host's §41 snapshot verbatim when a live connection serves it. `HostRuntimeHealth.kt` models the vocabulary exactly (`HostHealthState` up/degraded/down, six `HostHealthComponent` values, `ready`) and parses strictly through `WireValue.toJsonElement()`: every component and the readiness verdict must be present with the exact vocabulary — any deviation throws, and the fetch answers null, so a health snapshot never carries a guessed component. `fetchHostRuntimeHealth()` on `WireDriving` calls `hostDiagnostics/health` with empty args under a two-second `withTimeoutOrNull`, rethrows `CancellationException` (caller cancellation propagates into the export action's existing CANCELLED branch), and maps every other failure — unpaired wire, unadvertised capability (`host/capability-unavailable`), timeout, deviating shape — to null. `SupportLocalSnapshot` gained the nullable `runtimeHealth` field; the encoder emits a `runtimeHealth` segment (producer `hostDiagnostics/health`, observation `fetch-time`, six components plus `ready`) between the wire plane and `connections`, and `uncollected` keeps `runtime-health` ahead of `updates` whenever the snapshot is null — the three existing resource fixtures stay byte-identical in their null form. The `NativeObservedCapability` enum gained `HOST_DIAGNOSTICS("host.diagnostics.v1")` with `forEndpoint` mapping only `hostDiagnostics/health` (the companion consumes no describe/supportBundle operation), which makes negotiation advertise it automatically and lets the gateway's advertised-operation gate refuse unadvertised Hosts before dispatch. `SupportExportAction` takes the fetcher as a required parameter (no default — a future mount point cannot silently skip wiring) and runs it once per export attempt on `Dispatchers.IO`; both `MainActivity` mounts pass `CompanionRuntime.wire`.

## Alternatives considered

Lenient `WireShape`-style parsing with absent-fields-read-null was rejected — the health snapshot is the one place where a missing component must not be papered over; the strict parse keeps the whole answer honest. Fetching inside `CompanionViewModel.supportSnapshot()` was rejected — that function is synchronous and performs no I/O by design, and the export action's click-time capture precedent (`nativeExits`) already owns the async complement. A defaulted no-op fetcher parameter was rejected — explicit-over-implicit at the mounting boundary is cheaper than a silent uncollected regression. Mapping the `describe` and `supportBundle` endpoints into `forEndpoint` was rejected — the companion calls none of them, and an unmapped endpoint cannot be demanded by a stale callback.

## Consequences

A paired companion's support document now carries the Host's own §41 vocabulary — six component states plus the readiness verdict, in the Host's words, beside the uncollected list that still names `runtime-health` whenever nothing was collected. Two enum-driven joins landed with the capability member, both verified on the emulator lane: the diagnostics projection's fixed client-allowlist emits one more `supported` key (`"host.diagnostics.v1":false` — the `support-native-gateway.json` fixture updated to the honest 28-byte delta, the other two fixtures untouched), and the capability dialog's exhaustive `when` gained its branch with the locale-owned label `Host 运行时健康`. The JVM suite covers parse acceptance/rejection, fetch success, refusal shapes, virtual-time timeout, cancellation propagation, endpoint/args pinning, and the `forEndpoint` mapping; the support-export suite pins the collected projection, the null form, and the `uncollected` ordering. The connected round's eight failures decompose exactly along the gen-78 taxonomy (five notification-permission methods green in isolation, two stamp-requiring tests owned by the acceptance-APK lane per that taxonomy, one loopback-socket network test failing through an environment drift this generation's diff does not touch — recorded, not hidden). Process fact recorded beside the code: one accidental all-device `connectedDebugAndroidTest` run briefly installed the debug and androidTest APKs on the connected physical device before Gradle's own post-round uninstall removed them (read-only `pm` probes confirmed zero residue); the chain now pins `ANDROID_SERIAL=emulator-5554` (or direct `am instrument -s`) for every device lane, and the rule — no APK installs on any physical device without an explicit user request — is now written into the handoff red lines.
