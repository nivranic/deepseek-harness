# Agent Note: HTTP 响应清理识别已经断开的客户端

Status: implemented

[English](2026-09-26-http-disconnect-response-retirement.md) | 中文

## 问题

调用方可能在 Host 接受修改后、HTTP 处理函数返回前断开。向已关闭响应写入迟到结果会返回 false。只等待未来的 drain 或 close 事件会错过已经发生的关闭，导致桥接 Promise 始终未结束，原生监听器无法完成退出。进程重启验收也因此无法区分确认丢失与清理失败。

## 决策

共享 Node HTTP 桥接在处理函数返回后、每次写入响应块前，以及进入或离开背压等待时，检查响应是否销毁及断连信号。迟到的响应体直接取消，不写响应头；退出响应体迭代会取消未读取的块。已关闭响应不再等待下一次 socket 事件。处理函数在结束前仍持有自己的工作；桥接提供断连信号，但不把已经接受的 Host 修改伪装成被取消。

[Android 输入决策](../architecture/2026-09-26-android-encrypted-input-checkpoints.zh.md)拥有已保存的请求身份和显式重试。原生验收在真实 Gateway 准入后暂缓首次 RPC 结果，并在 Agent 产生 user-message 回执前暂停处理。随后强制停止应用，区分两种结果：回执产生前的显式重试沿用原请求 id；回执产生后的恢复直接核对，不再发送 prompt RPC。两者都保留新草稿，并再次重启验证。[原生入口决策](../architecture/2026-09-25-native-remote-connection-source.zh.md)继续拥有 TLS、设备权限及退出时等待所有桥接 Promise 的责任。

## 考虑过的替代方案

**同时等待 close 和 drain，但不检查当前状态。** 监听器无法观察注册前已经发生的关闭。异步工作后必须检查自己持有的响应与取消状态。

**断开时立即返回，放弃处理函数。** 这会丢失迟到响应体与剩余处理清理的所有权。桥接等待处理函数结束后取消返回的响应体。

**增加测试或关闭超时。** 错过的事件不会再产生完成信号，延长时间不能结束等待中的桥接。

## 后果

该行为同时适用于浏览器 HTTP 与原生 HTTPS 载体。断开不会撤回已接受修改，也不授权自动重放。确定性回归覆盖迟到处理结果、迟到响应块及背压期间断开；迟到结果用例在原实现上因观察到关闭后写入而失败。原生场景使用真实 Loader 产物，因此源码单元结果不能替代重建 Connection 包的 Node 入口。验收驱动在获取资源失败时，只有已成功创建 reverse 转发才删除它，保留获取前发生的原始错误。
