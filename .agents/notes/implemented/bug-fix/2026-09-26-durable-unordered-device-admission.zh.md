# Agent Note: 持久化设备准入接受乱序到达的全新证明

Status: implemented

[English](2026-09-26-durable-unordered-device-admission.md) | 中文

## 问题

独立签名请求可能按时间戳乱序到达 Host。拒绝所有早于最近获准时间的请求会误拒绝合法并发读取。仅持久化最新 nonce 还会在重启后遗忘同一时间戳下更早获准的证明，使其能在接受窗口内重放。

## 决定

Device Trust 在设备授权中持久化每个已获准 nonce 的 SHA-256 哈希及其签名时间戳。串行持久化更新重新检查撤销与有效期，拒绝已消耗哈希，并允许全新证明乱序到达。写入失败不消耗 nonce。最大时间戳仅用于最近活跃时间展示。

单调不减的准入下界淘汰早于当前窗口的记录，并拒绝低于该下界的证明。每次成功准入都持久化下界，防止时钟回拨或后续窗口扩大使已丢弃证明重新有效。等于下界的记录仍有效。每台设备的 `maxAdmissionNonces` 默认上限为 4096；达到容量时以 `device/admission-capacity` 及最早 `retryAt` 拒绝，不驱逐有效记录。该错误归为 `host-state`，客户端不会自动重试签名变更操作。

四键 `{deviceId, timestamp, nonce, signature}` 证明与三行 `deviceId + "\n" + timestamp + "\n" + nonce` 签名保持不变。nonce 区分同一毫秒内的合法请求。存储域版本 2 要求下界与完整记录列表；版本 1 被拒绝，不迁移用户数据。本决定取代[归档的高水位策略](../../archived/feature/2026-09-21-admission-nonce-ledger.md)。[Android 生产者决定](../feature/2026-09-21-android-adoption-device-admission.zh.md)继续拥有客户端签名与旧夹具。

## 考虑过的替代方案

**严格时间戳高水位：**合法独立请求会乱序到达，拒绝相等时间戳又会拒绝同一毫秒的不同请求。仅持久化最新 nonce 会使同一时间戳下更早的证明在重启后可重放。

**进程内 nonce 缓存：**重启会清除仍在签名有效期内的已消耗证明。旧夹具可验证签名，但不能验收原生准入的持久性。

**满容量时驱逐有效记录：**被驱逐的证明可以重放。显式容量拒绝既保留防重放保证，又限制存储量；记录过期后可继续准入。

**删除已淘汰记录而不持久化下界：**时钟回拨或配置窗口扩大可能使记录已消失的已消耗证明重新有效。

## 影响

每个已获准证明在时间戳仍可接受期间，跨重启保持已消耗。若捕获的证明先于原请求到达，它仍可成功一次：nonce 账本无法区分第一个提交者。TLS 固定、设备签名与本地 Web 认证仍是必要条件；本改动不放宽传输或 cookie 检查。

确定性 Host 测试覆盖乱序投递、同一时间戳全部证明跨重启的重放拒绝、并发重复准入、持久化写入失败、容量与过期、时钟回拨、窗口变化、排队期间过期与撤销、损坏存储记录，以及版本 1 拒绝。真实组合 Android 验证使用原生 Host 监听器；诊断 APK 在旧 Host 构建上观测到 `timestamp-regressed` 拒绝。Swift 验证仍由 CI 拥有，此 Windows 主机未执行。
