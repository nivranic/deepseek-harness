# Agent Note: index 起始标签的线性查找

Status: implemented

[English](2026-09-15-linear-index-tag-lookup.md) | 中文

## 问题

共享 index 渲染器在 Web 和 Desktop Host 中同步运行。用回溯正则表达式搜索完整起始标签时，如果许多标签前缀缺少结束的 `>`，就可能反复扫描文档剩余部分，阻塞启动或 index 响应。渲染器也接受片段和畸形标记，因此用浏览器解析替换其匹配规则会改变现有注入位置。

## 决策

[`renderIndexInjections`](../../../../packages/host/webserver/src/injections.ts)先查找首个大小写不敏感、后接 JavaScript 空白字符或 `>` 的 `head` 或 `body` 前缀，再从该分隔符开始查找首个 `>`。每次查找最多扫描输入两遍。不存在结束符时，使用现有片段回退行为。

匹配仍按文本进行：引号内的 `>` 和注释中类似标签的文本保留原有含义。属性、字母大小写、空白、原文档字节、行顺序和就绪尾部均保留。此工具不净化 HTML，也不校验注入内容。

## 考虑过的替代方案

**保留完整标签正则表达式。** 重复且未闭合的前缀可能导致平方级重复扫描。匹配定长前缀后只搜索一次结束符，可消除该原因而不扩大接受的文本范围。

**使用 HTML 解析器。** 解析会改变注释和带引号属性内的匹配，也可能规范化文档字节。当前消费方需要向所提供的文本插入内容；构建语法树会增加不同的语义和依赖，却无法更好地满足这一需求。

## 影响

畸形前缀不会导致反复扫描其后缀。渲染器保留宽松的片段行为，包括浏览器解析器会作不同解释的匹配。[Web 传输归属](../architecture/2026-07-24-web-config-tree-boot-and-transport-layering.zh.md)和[客户端加载](../architecture/2026-07-23-client-plugin-loading-model.zh.md)决策仍各自有效；此查找不改变其归属或启动协议。

必要验证包括两种放置位置的逐字节插入与回退用例、通过 Loader 组合的渲染器的行及 tap 顺序，以及在带超时的子进程中处理重复且未闭合的前缀，以便中断同步回归。不改变 Session 事件、模型可见输入或产品展示文案。
