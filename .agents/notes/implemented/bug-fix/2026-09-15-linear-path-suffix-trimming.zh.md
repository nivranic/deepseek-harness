# Agent Note: 线性移除路径末尾分隔符

Status: implemented

[English](2026-09-15-linear-path-suffix-trimming.md) | 中文

## 问题

工作区显示与文件地址工具接受字面路径。后缀正则可能反复扫描路径内部的长串分隔符，才发现后面的文件名使后缀匹配失败，从而阻塞调用它的浏览器或 Host 线程。

## 决定

[`workspace-path`](../../../../packages/util/workspace-path/src/index.ts) 从末尾向前扫描，在遇到第一个非分隔符时停止，以移除末尾分隔符。主目录缩写仍只识别 `/`；路径拼接、显示拆分和工作区相对化保留各自原有的正反斜杠规则。文件地址保留原有规范化与 Session 作用域。

## 考虑过的替代方案

**保留后缀正则。** 末尾锚点不能阻止模式在内部连续分隔符的每个起始位置重试。

**通过文件系统或 URL 解析规范化路径。** 这些工具必须保留未解析的点路径段与字面拼写。规范化会改变行为，也无法在浏览器中可移植地执行。

## 后果

移除末尾分隔符的耗时与后缀长度成正比。内部长串分隔符逐字节保留。[工作区文件服务](../architecture/2026-09-05-workspace-files-service.zh.md) 继续负责授权与文件系统解析；本改动不验证路径，也不改变资源地址。

验证保留 POSIX、Windows 盘符、UNC、混合后缀、根目录和主目录缩写的结果，以及现有地址语料。通过源码启动且有截止时间的子进程覆盖所有受影响公开工具中的内部长串分隔符，使同步重复扫描可以被中断，不会无限阻塞测试 worker。模型可见文本与资源地址语法保持不变。
