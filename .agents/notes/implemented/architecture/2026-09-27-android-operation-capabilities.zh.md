# Agent Note: Android 在原生操作前检查已声明支持的能力

Status: implemented

[English](2026-09-27-android-operation-capabilities.md) | 中文

## 问题

连接协商成功不表示所有 Session、Workspace 或文件操作都存在。呈现全部操作再通过失败发现缺失方法，会发送可避免的请求。仅隐藏按钮仍允许迟到回调和直接模型调用者发送不受支持的操作。支持情况改变时清空全部模型，则会丢弃无关的本地输入。

## 决策

伴随端依据最近一次成功的原生协商选择已识别操作。`NativeObservedCapability.forEndpoint` 镜像 Session、Workspace Files、Workspace 与 Subagent Remote 所有者声明的方法集合。`NativeGatewayClient` 在协商后、单次调用发送或 mux 订阅创建前检查该映射。缺少声明能力时返回 `host/capability-unavailable`，携带固定能力标识，不发送网络请求。成功刷新替换可用性；刷新失败保留最近成功观察。

Compose 使用同一组已识别能力标识隐藏不受支持的操作并抑制自动查询。会话列表、跟随与控制彼此独立。文件列表不要求 Workspace follow；文本读取与资源预览各有要求，预览同时要求 stat 和字节读取。子代理列表与子会话跟随彼此独立。已知不受支持与连接尚无观察分别呈现。

退休会话跟随和关闭资源视图不会删除加密草稿、待确认 prompt 身份或已保存的 Session 选择。恢复能力后可以重新打开观察，但不提交输入。子代理读取取消时保留现有行，回到 idle，不报告失败。停止请求被拒绝时显示未确认提示，不让异常逃出 Activity 协程。

能力描述 API 支持情况，不表示授权。该策略不会用配对时角色授予访问；Gateway 继续逐操作验证签名准入与权限。映射覆盖原生端拥有的方法集合，不覆盖任意扩展方法。内建 Gateway 事件传输没有虚构的能力标识，因此交互与推送消费者保留其既有协商协议规则。

[诊断决策](2026-09-27-android-native-gateway-diagnostics.zh.md)继续拥有安全观察与导出规则。其白名单包含公开的 Subagent catalog 标识，未知标识仍被排除。[传输决策](2026-09-25-native-remote-connection-source.zh.md)继续拥有 TLS、身份与退休规则。本操作策略不替代两者的理由，因此它们保持活跃。

## 考虑过的替代方案

**等待调用失败再隐藏操作。** 该做法将运行时失败误当成功能发现，还会发送 Host 从未声明支持的操作。

**把角色或能力当作授权。** 已声明的方法仍可能被当前 Host 策略或设备撤销拒绝。客户端呈现不能替代准入检查。

**能力集合改变时重置全部模型。** 独立观察与输入具有不同所有者。仅关闭不受支持的观察可以保留用户的本地意图，避免意外重提。

## 后果

基于 TLS 的测试验证缺失能力时 HTTP 与 mux 计数不变，并验证刷新能够移除和恢复支持。已安装 Activity 连接真实 Host，方法保持挂载而能力声明改变；调用观察独立于界面断言证明请求被抑制。场景覆盖草稿保留、操作恢复与停止请求拒绝，且不自动提交 prompt。既有权限、文件、输入与诊断场景覆盖相邻路径。完整跨版本行为、物理设备及其他原生功能仍是独立验收工作。
