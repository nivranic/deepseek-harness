# Agent Note: 托盘偏好和登录注册由 Desktop Shell 拥有

Status: implemented

[English](2026-09-15-desktop-shell-preferences.md) | 中文

## 问题

隐藏 Desktop 窗口需要原生恢复入口，并且该入口在 Host 启动或失败时仍需可用。登录注册可能被应用外部禁用，因此持久化布尔值不能证明操作系统会启动应用。通过 Host 设置共享这些控制会让原生生命周期依赖后端可用性。

## 决策

官方 Electron Shell 拥有原生菜单、托盘和串行写入的关闭偏好。[Desktop 用法](../../../../apps/desktop/README.zh.md#tray-and-login-startup) 负责说明默认值、文件格式、错误行为和用户控件。应用渲染进程不增加 IPC，Host 设置命名空间不包含 Shell 偏好。

单实例所有者接受偏好写入。Shell 必须先创建带恢复和退出操作的托盘，才能阻止关闭或隐藏登录启动的窗口。禁用偏好会先显示窗口，再销毁托盘。退出会拒绝新修改，等待已接受的写入，然后销毁托盘。更新器在停止 Host 前等待偏好写入；更新错误会释放安装器的退出控制权。

打包应用的可执行文件和固定 `--hidden` 参数标识操作系统登录项。系统读取结果决定复选框状态，包括 Windows 可执行文件启用状态和 macOS 审批状态。开发模式和不支持的平台不能通过此适配器读取或修改登录注册。原生激活和第二实例会显示主窗口，不创建另一个 Host。

旧版导入通过原生文件选择与显式确认执行。有大小上限的 JSON/YAML 读取器只提取 Desktop 字段，拒绝未知版本和错误字段，不引用源文件内容，并以所选文件摘要绑定确认。现有 Shell owner 使用托盘与原子写入保障应用关闭行为。旧登录偏好仅展示，不能注册登录项；源文件及其其他 namespace 均不重写。并发导入被拒绝，退出或安装器接管后不接受新变化。

## 考虑过的替代方案

**把原生行为存入共享 Host 设置。** 这需要后端启动，并增加控制 Shell 生命周期的通信路径。原生菜单和 Shell 自有文件使这些操作不依赖 Host。

**把登录启动状态与关闭行为一起持久化。** 复制的布尔值可能与系统策略或用户在系统设置中的修改不一致，因此 Shell 直接查询注册状态。

**默认启用后台关闭。** 这会在用户未选择时改变平台的普通关闭行为。默认值保持禁用，托盘失败也不会让窗口困在后台。

**启动时自动发现并迁移 Host 设置文件。** 自动发现可能在未经核对来源选择时打开历史 Harness home，并在没有当前同意时恢复系统启动行为。显式预览保留原文件，要求用户选择当前关闭行为；OS 登录仍由单独控件管理。

## 影响

原生偏好在 profile 修复后保留，但不会跨设备同步。旧版导入仅转换关闭行为；用户单独检查 OS 登录注册，并保留完整旧文档。[收敛计划](../../../../docs/plans/2026-09-14-upstream-first.zh.md#task-2-converge-desktop) 将更广泛的数据转换保留为显式操作。

归属目录内的菜单快照和生命周期测试覆盖用户控件、持久化拒绝、写入失败、退出和更新器错误。Windows 开发运行验证了真实托盘、关闭隐藏、第二实例恢复，以及独立 Node Host 下的显式退出。操作系统登录注册、打包应用行为和 macOS 执行仍属于平台验收要求。
