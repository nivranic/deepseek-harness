# Agent Note: Android 将完整资源快照保存到用户选择的文档

Status: implemented

[English](2026-09-27-android-complete-resource-save.md) | 中文

## 问题

有界资源前缀适合检查，但不能代表完整文件。系统文档选择器也可能在资源导航、Host 替换或进程丢失后返回。回调时使用当前选择可能保存无关字节；重复结果再次执行清理则可能删除已接受的文档。

## 决策

文件与工件预览仅对完整 READY 观察提供保存。开始保存时复制已接受字节，并保留确切观察及 Host 持有的保存器。系统通过 `ACTION_CREATE_DOCUMENT` 仅接收文件名和检测到的 MIME 类型；用户与文档提供方决定最终名称和位置。保存不增加 Host 读取或写操作。这是有界内存快照，不是持久下载，也不承诺 Host 文件此后保持不变。

应用在根部注册一个选择器。Activity 作用域的持有者跨 UI 重建保留原保存器，并仅消费一次待处理结果。它不保存可跨进程恢复的资源批准。恢复后的持有者若没有选择，会清理新建目标而不写入。为另一个资源清除完成态提示，不会重置结果已消费标记。

资源替换和关闭使待处理选择失效，并取消持有的写入。Host 退役通过模型生命周期等待写入及清理。交付在报告成功前关闭并刷新输出；失败或取消会尝试删除该新建文档。清理失败即使发生在取消后也保留独立结果，告知用户可能遗留不完整文件。迟到的选择器结果不能消费另一资源选择，重复回调也不会删除已保存文档。

[资源读取决策](2026-09-27-android-current-resource-reading.zh.md)保留字节校验、预览限制与重试规则。[已保存 Host 决策](2026-09-26-android-saved-host-catalog.zh.md)保留主体采纳与等待模型退役规则。两者继续有效。资源导出不使用诊断导出要求的扫描器批准，因为它有意保存用户选择的文件内容，而非支持报告。

## 考虑过的替代方案

**保存显示的前缀，或在选择器返回后重读。** 前缀并不完整；另一轮读取可能遇到不同版本或 Host。仅捕获已接受的完整字节，才能保留用户选择的内容。

**写入固定公共路径，或将认证 URL 交给 DownloadManager。** 文档选择器提供显式目标选择。当前 Gateway 读取需要签名准入和不透明版本检查，通用 URL 下载不能保留这些规则。

**持久化待保存批准，或关闭状态提示时忘记已消费结果。** 恢复批准需要绑定主体的持久传输协议。重新接受重复回调可能删除此前保存的文件。本操作仅在内存中保留批准，并将进程丢失视为失效。

## 影响

核心测试覆盖字节捕获、零字节内容、部分内容拒绝、取消、迟到与重复回调、写入失败、清理失败、重入退役及等待 I/O。安装态测试检查选择器 Intent 和回调归属。真实 Host 场景驱动系统选择器，独立读取保存的中文、空及二进制文件；同时验证取消、失效清理和部分预览没有保存控件。持久大文件下载、崩溃安全的传输恢复、第三方文档提供方及物理设备布局仍是独立资格工作。
