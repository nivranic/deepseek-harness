# Agent Note: Android 通过有界 Host 历史显示共享 Session 位置

Status: implemented

[English](2026-09-26-android-native-view-location.md) | 中文

## 问题

原生伴随端若只保留最新 follow 窗口，就无法显示较早的共享位置。分页使用不断变化的日志截止点，或在 Session 替换后接受迟到结果，会混合不属于同一窗口的记录。未接入当前应用的 Lite Handoff 协议会创建另一个 Session，因此不能用于转移查看位置。

## 决策

Android 使用既有 [Session Controller](../../../../packages/api/session-controller/README.zh.md) 的 v1 位置格式：带前缀的 base64url 载荷包含 Host id、Session id 和安全的非负持久序号，不含凭据。编码遵循 Web 的 ASCII JSON 限制；解码检查精确字段和调用方提供的字符上限。打开流前必须匹配当前已信任 Host；导入不依据载荷选择或信任 Host。

一个原生日志持有初始快照截止点、有序保留记录及向前分页请求。每页使用该固定截止点和当前最早序号；实时事件继续追加到快照之后。快照和分页替换折叠窗口，实时事件则增量折叠。传输数据检查拒绝缺失分页元数据、不安全序号、缺口及没有进展的分页。原生界面保留既有原始事件摘要，本改动不替换其呈现语义。

Session 模型提供可配置的分页及保留上限，默认每次请求 50 条消息、保留记录序列化字节最多 8 MiB；这不代表总堆内存测量。较早页面被拒绝时保留当前窗口并提供手动重试。应用打开时不自动下载全部历史。显式锚点导航只向前读取到覆盖目标，或被失败及上限终止。

快照或 Session 替换会取消旧分页并使其结果代际失效。取消的读取在完成前仍受持有；可挂起的模型退出会等待清理结束。共享位置跳转也属于模型生命周期，可在等待首个快照时取消。完成跳转携带导航代际，因此再次打开相同序号仍会请求新的滚动。定位完成后，后续实时数据不会持续把视口拉回原处。

UI 复制第一条可见持久记录，并导入粘贴的位置。待发送输入没有持久锚点。导入遵循 Host 的既有观察与激活策略，既不创建另一 Session，也不调用退役的运行时迁移方法。草稿继续按[输入保存决策](2026-09-26-android-encrypted-input-checkpoints.zh.md)归属于主体，Host 切换继续由[已保存 Host 目录](2026-09-26-android-saved-host-catalog.zh.md)管理；这些决策及原生 TLS 决策继续有效。

## 考虑过的替代方案

**使用旧 Lite 快照传输。** 该协议请求新的完整 Session，并携带运行时派生内容。查看位置 Handoff 则标识既有 Host 日志并保留其归属。

**预加载全部对话，或每页使用最新游标。** 无界启动工作超出移动端预算，变化的截止点也可能混合不一致历史。显式有界分页保留初始截止点，并使用固定的内存计量上限。

**取消后立即放弃请求持有。** 取消可能先于传输清理完成。保留任务与代际检查分别保证退出时静止及拒绝迟到结果。

## 后果

core 测试覆盖 Web 兼容编码、错误 Host 拒绝、历史与实时合并、迟到分页、读取失败、字节上限、取消读取退出及重复导航。真实 Host 场景向已安装 Android 应用提供 88 轮生成 Session，在不增加观察流的情况下拒绝错误 Host，重试被拒页面，并通过 Web 解码器核验复制的可见锚点。整个过程不提交 prompt 或新建 Session。这是预置历史的传输证据，不代表真实模型提供方已通过验收。深链接、平台分享路由、Swift 采用、物理设备及工件读取仍是独立工作。
