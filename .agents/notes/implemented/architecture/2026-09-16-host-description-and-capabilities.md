# Agent Note: Host discovery uses persistent identity and live Remote bindings

Status: implemented

English | [中文](2026-09-16-host-description-and-capabilities.zh.md)

## Problem

A Client's generated Remote imports describe its selected APIs, not the capabilities currently mounted on the connected Host. Product release, API generation, and Session writer generation also answer different compatibility questions. A label or best-effort telemetry id cannot provide persistent Host identity when launches contend or storage fails.

## Decision

[`host.describe`](../../../../packages/api/host-description/README.md) uses the existing authenticated Typert Remote path. It returns a persistent random Host id, an operator label, three independently owned versions, Host process facts, configured carriers, and the current explicit capability ids. The Host id is scoped to its configured file and is not a device credential or an authorization decision. Creation reuses the shared file lock and atomic writer; corruption and I/O failure reject startup without replacing the identity or inventing an in-memory substitute.

Capability declarations belong to existing [`TypertGatewayBinding`](../../../../packages/typert/protocol/src/index.ts) objects. Each versioned semantic id names the exported methods required from its owner. The Gateway advertises declarations from live bindings only while all required method definitions are available. Service disposal and strict-definition withdrawal remove availability. Duplicate ids, missing exports, and inconsistent providers fail explicitly. The generator accepts this runtime metadata without changing invocation codecs or relaxing unknown-option checks.

The API Remotes facade mounts the generated `host` contribution alongside the selected business APIs. Session Controller declares its follow, live-control, management, and model-selection operation sets. The [Remote method decision](2026-08-02-typert-remote-method-calls.md) remains active: generated imports do not prove Host availability, withdrawn strict definitions cannot fall back to SRC, and capabilities do not replace invocation validation or authorization.

Workspace follow, registry management and Session organization have independent declarations in the [Workspace Controller](../../../../packages/api/workspace-controller/README.md). The Client waits for follow support through Gateway's existing stream lifecycle, without restarting again on connection admission. Host snapshot replacement clears projection and mutation authority; pending unary replies cannot update the replacement state. UI callbacks and directory adoption observe that same snapshot, while unavailable projection preserves browser view preferences. Already dispatched Host mutations remain effective; these checks do not supply mutation receipts or Device authorization.

Directory picking advertises the operations served by the stable backend capability, rather than every method exported by its controller. Native picking, directory browsing and creation have independent operation sets. Client occupants register transactionally only when their operation is advertised and bind calls to their Host snapshot and registration lifetime. Disposing that lifetime cancels reads and native selection; a dispatched creation can still commit, but its late result cannot relist or adopt a directory on another connection. This preserves Host side effects without confusing them with a current Client selection.

Logical stream admission and delivery use the authoritative Connection generation id. A Remote failure from an obsolete generation cannot terminate the stream intended for its replacement; delayed frames are discarded before delivery. Isolated retry accounting resets on a different admitted Connection, while same-connection limits and terminal local errors remain intact. This keeps Workspace projection recovery inside Gateway and prevents an empty replacement projection from becoming a permanent Client view.

Retained interaction answers belong to the validated Host identity supplied by application discovery. Event id and revision alone cannot distinguish different Hosts reached through the same carrier. Gateway therefore requires an explicit reply scope and a matching pending snapshot before replay; missing identity requires the listener to answer again. Old acknowledgements may clear only their own saved-answer object, so an obsolete connection cannot erase a replacement Host’s answer. This is in-memory retry ownership, not device authentication, response authorization or a durable mutation receipt.

## Alternatives considered

**Infer capabilities from package versions or method names.** Neither identifies a versioned business promise. Explicit declarations let an owner name the complete operation set and its supported semantics.

**Maintain another capability registry.** Remote bindings already follow Service lifetime. A second registration path could retain a capability after its implementation disappears.

**Reuse the anonymous telemetry id.** That id deliberately permits temporary identities after persistence failure and convergence after a concurrent first launch. Host selection requires stable identity or an explicit failure.

**Reuse one version field.** A package release can change without changing the API or disk format; a Client must not infer any one of those generations from another.

## Consequences

Every Gateway RemoteStream waits for an admitted Host before its opener, whether or not the domain supplies a capability predicate. This prevents Workspace startup from becoming terminal while initial discovery is still connecting; Connection remains the readiness and retry owner.

Workspace selection, including blank-Session reuse, requires `session.manage.v1` before claiming navigation. Creation and fork recheck it before selecting their result or moving a draft; capability withdrawal leaves completed Host mutations intact. Automatic startup selection waits for support and resumes from Connection updates without duplicating a pending attempt. Direct selection of an existing Session remains available. The Conversation Workspace picker hides and closes without reopening when management returns.

The Conversation shell derives one `historyAvailable` owner prop from admitted Host facts for each selected View. A localized notice distinguishes unavailable history from loading while cached rows and drafts remain visible. Chat suppresses remote paging and unloaded-turn navigation; Trajectory retains resident paging but stops Host history reads. The browser regression exercises actual carrier replacement and history catch-up against a real Host with a controlled capability advertisement.

The sidebar's New Session shortcuts require `session.manage.v1`. The existing renderer binds a boolean derived from admitted Host facts; replacement rechecks availability without a second store. Brand identity and non-creation navigation remain available, while retained creation callbacks cannot navigate after capability withdrawal. Workspace-row creation and grouped/flat Session rename/fork actions use the same admitted capability. Withdrawal closes open Session menus and rename dialogs without reopening them on restoration. The preset Settings creator checks capability before staging a preset or navigating; its renderer hook hides the action while ordinary preset operations remain available.

Session Controller shares its explicit capability declarations with Client admission. Gateway checks each declared Session operation before unary or stream dispatch, so hidden UI and retained callbacks use the same operation policy. The control and event journal streams wait for their respective capabilities on an admitted generation instead of treating capability absence as a terminal stream failure. The journal retains its published window during that wait and replaces it after restoration; disposal releases the waiting observer. Conversation controls become read-only while preserving the draft and restore on a capable generation; Connection still owns reconnection.

The Client assembly installs discovery before exposing its selected business namespaces. Gateway runs it under the existing Connection attempt signal, before opening the forwarded-event stream; business calls wait for both discovery and event readiness. The descriptor belongs to that generation, so loss clears the advertised facts and cancels its admitted calls. A pending caller can cancel independently. Preparation withdrawal fails closed, and late completion from a cancelled attempt cannot publish readiness. Connection remains the sole retry owner.

The generated result codec validates discovery; the API discriminator is checked first so an unknown generation produces an explicit incompatibility result without applying the current generation's remaining codec. The discovery representation remains protocol 1 for frozen Clients. Explicit negotiation offers select the highest shared request codec, 2 or 1; missing negotiation metadata identifies a protocol-1 Host without probing unavailable methods. Contradictory metadata, changed identity, or negotiation failure rejects admission without downgrade. Discovery does not grant permission. Native DTO consumers, capability-based UI admission, and a dedicated upgrade interface remain incomplete. Session events and disk formats are unchanged.

Unit tests cover identity contention, persistence failures, capability withdrawal, and unchanged generated invocation declarations. The real Web Loader test reaches the authenticated HTTP Remote route, rejects anonymous discovery, and compares the returned identity with its isolated Harness-home file. Desktop carrier configuration is checked separately; these results do not qualify a new installer, native companions, or real-model execution.

Gateway owns carrier request version parsing in a face-neutral protocol module. The version-1 encoder retains the unversioned argument envelope; version 2 carries an explicit discriminator. Both unary and stream dispatch validate explicit versions before endpoint handling, including reserved event endpoints. Unknown versions cannot invoke business methods or register event Clients. Application preparation returns the selected codec explicitly, and each generation retains it for business calls and event replies. Negotiation grants no authority. Real HTTP tests execute current and frozen protocol-1 API bundles in both directions; shared workspace dependencies are unchanged, and this evidence does not qualify complete old releases.

Model selection consumes the admitted `model.select.v1` fact before rendering either entry or reading its catalog. The directory executor rechecks availability so retained callbacks cannot send unsupported operations. The slot renderer binds the Host-generation observable directly; there is no separate capability store. Generation loss removes old catalog data and routing blocks, while the command owner dismisses generation-bound popups without moving focus. Capability presence still does not grant operation permission. Other feature entries require their own capability admission.

Agent Presets declares catalog, selection, and management independently through the existing Remote binding. Client admission consumes the same pure declaration leaf. Missing catalog support suppresses roster and directory-opener probes and removes the Settings registration; advertised invocation failures remain errors. Selection withdrawal discards staged picks, management withdrawal closes copy/delete drafts, and retained callbacks check current facts before dispatch. Historical labels remain projection-owned. This preserves catalog access on Hosts lacking selection or management without adding a capability store or retry owner. Settings preference and directory capabilities remain a separate owner and are not authorization guarantees of the preset operation sets.

Settings Controller independently declares redacted reads, writes, settings-document opening, and preset-directory operations through its existing binding. Gateway checks the exact owning operation set. Preset preferences and location controls use Settings support separately from preset catalog/management; unavailable preference writes cannot trigger blank-Session synchronization, and copying a preset does not require or probe a directory-opening API. The declaration promises callable semantics, while provider absence, writability, native-opening policy and permissions remain checked by the operation. Other capability owners still need their own capability-driven UI behavior.

The shared Settings mirror admits reads from the current Host capability facts before dispatch. Connection replacement clears its document, effective writability combines Host support with provider writability, and per-namespace scopes retain display values while dropping revision authority. A write requires an accepted namespace from the same generation; early gestures and queued predecessors are never replayed on a new Host. Late results cannot publish or supply the next generation’s revision fence. The document action also checks its metadata generation and document-opening capability. Cold boot starts one shared describe after discovery, rather than making a speculative pre-admission read. These changes reuse the existing mirror, queue and Connection invalidation event.

LLM and credential bindings now own their directory, discovery, metadata and write capability sets. The Models join admits reads before dispatch and clears previous views when the admitted Host snapshot changes. Editor callbacks capture that snapshot; the existing page projection supplies a generation key that discards local editors and secret drafts on replacement. This prevents a late first step from sending a second write through a new connection. Missing APIs remove their entrypoints; provider permission checks remain independent. Other capability owners, complete compatibility/error coverage and Device Trust enforcement remain unfinished.

The Web-search configuration consumer now follows the credential owner declarations after current Settings namespace acceptance. Connection replacement disposes its controller and staged secret state, while a same-reference read counter prevents late metadata from replacing a newer answer. The shared card form invalidates multi-step saves when the scope loses its accepted namespace or its owner disposes it. This also protects ordinary plugin-card writes across reconnects and preserves input staged after a save began. API support, provider writability and Host permission remain separate facts.

Workspace Files owns independent operation declarations. The Client file provider requires metadata support, captures its admitted Host snapshot, and aborts registration-scoped work on replacement. Metadata-only Hosts yield a one-shot stat; changes support adds the existing shared Session feed and readiness ordering. Held resources restart with a fresh stat after replacement, so writes missed while disconnected do not leave an old metadata version authoritative. A feed cancelled while waiting for its predecessor never dispatches. Filesystem access, file-list UI and renderer entrypoint decisions remain separate concerns.

File-list and document-preview registrations now belong to the admitted Host snapshot. Listing, metadata, text pages and complete bytes remain independent, and HTML declares its additional related-file requirement. Withdrawal removes operation entrypoints while retained tab identity stays with the Sidebar. Replacement aborts old reads and discards the owning content store, avoiding stale file content after reconnect. Renderer availability changes notify the tab registry without replacing tabs; that registration owns and rolls back its observer. Related-file readers also capture their registration and reject late results. Composer references and sent-message file and skill chips derive eligibility from the same viewer registry. InputTrigger publishes source, lexicon and viewer changes; read-only eligibility never fetches, and the executor rechecks it. Skill previews require a settled catalog path, while normal warming and menu discovery retain catalog ownership. Eligibility stays out of draft serialization and Session history. Chat binds these observations through renderer hooks and releases optional-source subscriptions with its readers. Tool path summaries, produced-file chips, explicit delivery previews and closing prose use the same owner query, propagated through the existing Tool and Turn-tail props. Withdrawal keeps file names, result disclosure and durable facts while removing preview controls; resolved prose actions also recheck eligibility. Native file menus retain their separate Host metadata and action policy. Other capability owners remain separate unfinished work.

Reference discovery retains the registered sources because they also own draft serialization and preview routing. File, Session and skill discovery each require their owner-declared capability, without using failed calls as feature detection. Candidate invalidation has its own subscription, separate from lexicon changes; it cancels old queries and removes rows and headers synchronously. Connection readiness retries source warming so a catalog suppressed before discovery can become available without another keystroke. File preview eligibility stays viewer-owned, while skill previews also require the current settled catalog. Late responses cannot restore an old Host catalog or candidates.

Deferred candidate refresh belongs to the menu query generation, not one parser-produced hit object. The editor can re-detect an equivalent hit while source invalidation waits for other observers; that preserves the query and uses its latest span. A newer query, a closed menu or disposal still rejects the queued refresh. This prevents an invalidated menu from remaining pending without a live candidate request.

Native delivery actions use a generated Remote contribution from their existing owner. This lets Host discovery derive desktop metadata, open and reveal capabilities from active methods without a second registry or fallback HTTP route. Each operation keeps Session-event ownership, filesystem-to-Host mapping and native policy checks. The Client requires accepted current-generation metadata and the specific action capability; losing either removes its entry. Generation loss cancels metadata and native requests, clears transient status and discards late results without replay. Structured errors preserve missing files, unavailable desktops and absent native paths without exposing private paths. The timeout dependency classification keeps one shared `TimeoutReason` identity through peer installation rather than adding a duplicate-install exemption.

Session search and durable image retrieval declare separate operation capabilities on their existing Remote owner. Gateway admission and generation cancellation remain shared; the Session layer adds no second connection lifetime. Workspace search observes immediate Connection generation withdrawal, retains local metadata matches and query text, and repeats only the current read when support returns. An equally capable replacement also invalidates completed content hits. Attachment capability admission does not replace Session-log authorization.

The Settings mirror subscribes to Connection generation changes so withdrawal clears the shared document before reconnection completes. The permission default editor requires its descriptor and both Settings capabilities from the current generation. In-flight writes retain their originating Host; replacement discards their success and failure without replay, and an independent new-generation selection can proceed. Disposal rejects new gestures and waits for pending writes. Test fixtures explicitly declare Settings support instead of relying on namespace presence.

Native Client actions accept durable file-declaration coordinates through the declared-file owner. Session Controller keeps native path opening and desktop metadata local to Host services; its generated Session namespace exports neither helper. The unused availability query is removed. This prevents a parallel arbitrary-path Remote API from bypassing the declared-file authorization flow. Generated Client types, the controlled Connection fixture, authenticated HTTP routing and direct Gateway dispatch all reject the local method names; Host adapter tests preserve local open and reveal behavior.

Commands declares independent catalog and execution capabilities. The existing Connection generation source invalidates the directory and candidate menu immediately, while directory epochs still handle ordinary soft refreshes. Pending Enter adjudications cannot adopt a replacement catalog; retained input claims and Host candidates keep their originating Host identity. Late execution success and failure cannot acknowledge a new submission, and detached replies publish no stale notice. The gateway retains transport cancellation ownership. Independent Client contributions remain available under their own predicates; Host decorations require a current executable descriptor. The real-Host browser case delays delivery after an isolated command handler runs, then withdraws support: the draft survives and restoration sends no second execution. That observation proves response ownership and no replay, not rollback of an accepted Host mutation.

Goal Remote operations advertise separate capabilities while the domain retains revision and transition checks. The dock combines the read capability with each action declaration, and its activation source observes immediate Connection withdrawal. Supported callbacks capture Host identity before reading the current projected revision and invoking the existing Remote method. A replacement authority snapshot gives the GoalBar a new component key, deliberately discarding Host-owned editor and pending state while preserving the separate message composer. Old action results cannot close the replacement editor or hide its goal. The activation source contains transport rejections and suppresses unsupported reads; lifecycle and durable phase remain distinct. The browser case seeds a disarmed Goal, accepts one actual edit, cancels delivery on reconnect and retains an independently opened replacement editor without replay.

Subagent catalog, prompt and parent-addressed interruption advertise independent operation capabilities. Catalog withdrawal clears transient membership, parent-availability hints and open menus but retains durable child addresses, the selected Session and its draft. Catalog requests own their generation and pending slot, so an old completion cannot remove a replacement request. Composer prompt and Stop controls resolve independently; one-shot records stay read-only. Stop callbacks capture Host and child address, while child submission checks Host identity across image serialization and response settlement. These Client checks prevent stale dispatch and UI publication; they do not roll back accepted Host mutations. [The continuation owner](../feature/2026-07-28-continuable-subagent-conversations.md) recognizes repeated Prompt identities; addressed interruption captures the observed child turn, while the legacy method retains current-turn semantics. Durable parent ownership and live activation remain Host responsibilities.

Feedback operations declare message read, put and delete independently from Session remark recording. The Client requires a read before message CAS mutation; a read-only rating remains passive, and unsupported reads never probe the Host. Existing Connection withdrawal clears item versions, queued-operation ownership, dialogs and notices. Reads and mutations capture the originating Host before waiting, and old responses cannot replace a current version or release a replacement request. The dialog uses a separate connection epoch so same-connection draft dismissal can still acknowledge a committed remark while a replaced connection cannot. This preserves existing message durability and Session log-only semantics without introducing replay or claiming idempotency.

File staging uses one owner declaration for the generated Remote and raw-byte carrier. The Client upload service depends on Connection and Gateway types without depending on the application Remote assembly; the shared capability failure code therefore belongs to Gateway. Cancelling the originating generation prevents stale transport work from admitting receipts. The composer additionally invalidates completed receipts, which would otherwise survive without an active request to cancel. Browser-owned files and images remain drafts, but support restoration never restages them automatically. Native chooser callbacks and attachment serialization retain their originating Host identity. These rules prevent cross-connection publication and replay without implying rollback of stored bytes.

Plugin inventory declares one read-only capability independently of preset and Settings access. The Settings tab registration belongs to one Connection generation and captures its Host. A fresh component identity resets Host-owned search, selection, expansion and menu state even when replacement preserves the same capability set. Withdrawal aborts reads and removes the entrypoint; retained callbacks reject before dispatch, and late results cannot enter the replacement page. The Host checks cancellation around preset discovery without adding a second Loader cache.

Dynamic Cordis operation declarations are independent because inventory and inspection can be available without execution or mutation. A two-half run admits its required sequence before the first Host activation. The page orchestrator and load engine each own a Connection generation: withdrawing the former prevents follow-up RPCs and stale attempt settlement, while withdrawing the latter prevents late module registration and invalidates closures held by old Client code. Per-Plugin queues retain teardown order before replacement loads. Inspect publication drops old queued work and detaches the replacement chain from stalled earlier reads; query cleanup checks exact controller ownership. These Client lifetimes do not roll back an already accepted Host activation.

The Dynamic Cordis panel and completion source also belong to one generation. Fresh registration remounts the panel on equally capable replacement connections, so old selection, errors and pending callbacks cannot acquire the replacement inventory. Recorded tool-card ownership stays Session-derived. Refusal is independent of activation: a Host that advertises request resolution can expose pending requests without granting the page permission to start them. Package-level operation requirements live in the [UI reference](../../../../packages/extensions/ui-cordis/README.md).
