# Agent Note: Lite 对话界面骨架

Status: implemented

[English](2026-08-30-lite-chat-ui-skeleton.md) | 中文

## 问题

Lite 运行时已有循环、折叠、存储与提供方缝，但没有界面：用户无处输入、看不到流式、看不到工具运行、也不会被告知发生了移交（第 35 章"在 <宿主> 上继续"的时刻）。

## 决策

`LiteChatViewModel` 把一个端上会话绑定到循环：`send` 驱动 `LiteLoopDriver`，随后把该轮折叠可见的结果事件记入 `LiteSession` 日志，配置了 `LiteSessionStoring` 时保存；`state` 在轮次运行时暴露驱动器的实时折叠，否则暴露日志重放。`LiteChatView` 直接渲染行为规范状态——带中断标记的会话行、流式部分、带阶段的工具行、artifact 引用、以及点名在宿主上继续的能力的移交横幅。真实提供方与脚本提供方都可原样插入。

## 后果

端上循环端到端打通：输入、流式、工具派发、移交、持久化、重启重放。日志保留轮次结果（prompt、完成消息、移交或完成）而非原始流增量——刻意的骨架简化，重放保持廉价；产品需要 token 级保真恢复时再加增量级日志。测试覆盖提交-持久化-恢复与移交横幅状态。Swift 在本机仍是已编写未编译（既有的 macOS 车道告解）。

## 考虑过的替代方案

为每个流增量写日志被延后——折叠层已定稿前缀，第 64 章禁止过早保真。独立移交页面被否决——一条横幅在点名工作去向的同时保住轮次上下文。
