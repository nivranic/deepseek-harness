# Agent Note: 第 34 节差异预览的分屏视图

Status: implemented

[English](2026-09-30-diff-split-view.md) | 中文

## Problem

第 34 节 Diff Viewer 一直把 `.diff`/`.patch` 渲染为单一 unified 序列。规格要求所有载体默认 unified、桌面级表面可加分屏呈现，包 README 把「分栏 diff 仍为未实现的可选项」记为延期工作。

## Decision

- 纯配对模块（`diff/split.ts`，无 React/DOM）把已解析的 unified 行转为分屏行：上下文行出现在两侧；每个无上下文衔接的删除/新增连续段按位配对（首个删除对首个新增），较长一侧的多余行对着缺席对侧；前导、hunk、note 行保持整行并保留 unified 索引，文件链接与语法高亮继续按源行寻址。
- `DiffBody` 在现有工具栏加按 tab 生效的视图切换（`aria-pressed`）；所有视口默认 unified，满足手机默认，桌面读者按需切分屏。分屏行复用同一虚拟化器——一个配对行仍是一个虚拟行——每半各渲染自己的行号、符号、变色与经该侧 unified 索引查得的共享语法 span。整行分屏行（文件头、hunk、note）与 unified 行完全同渲染，保留当前文件打开动作。
- 证明：纯配对单测覆盖按位替换对齐、纯删/纯增、长侧尾部、边界冲刷与索引保留；组件测试覆盖默认视图、经 `data-diff-view`/`data-diff-side-kind` 语义的切换往返、空白对侧；`diff-preview.e2e.ts` 扩展真浏览器车道——切入分屏、带各自行号的配对半边、旧左新右的几何布局、切回 unified——golden 增加分屏行。

## Alternatives considered

- **跨 tab 或跨会话持久化所选视图：** 查看器级偏好存储为一次点击的切换引入状态归属；按 tab 的临时状态让表面保持局部，持久化继续延期。
- **配对行内再做词级对齐：** 第 34 节共享能力清单止于 hunk/增/删；行内对齐是带独立成本的另一特性，不纳入。
- **单独注册分屏渲染器：** 配对只是同一批已解析行在同一滚动区、分页、复制、打开文件接缝上的投影——带视图状态的单渲染器避免复制每个共享能力。

## Consequences

- 差异预览同时提供第 34 节两种呈现；虚拟化、分页、复制、语法高亮与当前文件打开在两视图间共享而非分叉。
- README（双语）用分屏契约替换延期工作句。

## Open work

- 切换按 tab 生效，重开回到 unified；无跨 tab 或持久化偏好。
- 配对行内无词级高亮。
