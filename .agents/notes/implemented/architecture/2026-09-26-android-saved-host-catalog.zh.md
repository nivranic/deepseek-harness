# Agent Note: Android 同时提交已保存 Host 的选择与凭据

Status: implemented

[English](2026-09-26-android-saved-host-catalog.md) | 中文

## 问题

单一凭据文件会在配对另一 Host 时丢失之前保存的 Host。把当前选择与凭据分别持久化，可能在中断后恢复不同身份。在停止旧模型工作前发布新 Host，则可能使操作通过与界面选择不同的连接发送。

## 决策

Android 使用版本 1 加密目录，同时保存全部原生授权与当前 Host 键。键由 Host id 和 TLS 指纹的哈希确定；端点和可替换的设备授权不构成另一 Host。重新配对替换该 Host 保存的授权。应用使用独立 Keystore 别名和 1 MiB 文档上限。解码拒绝无效身份、重复 Host 键、不支持的字段或版本及悬空选择。同目录原子替换同时提交凭据与选择。

ViewModel 隐藏业务控件，并在切换 Host 前等待模型退出。控制器先保存旧主体输入，再准备目标传输与输入，最后不可取消地提交存储并采纳。提交前失败保留旧选择并退出候选资源。提交后旧资源退出失败时，保留已提交身份的显示，但在进程重启前禁用操作；不会把旧身份重新发布为仿佛持久化提交未发生。新模型只恢复观察；已保存输入不会自行提交。

目录不存在时可显式导入之前的原生凭据文件。导入保留原文件并拒绝旧 Link 凭据。目录建立后，应用不再回退到旧文件。不可读取的目录必须显式备份并替换为空目录，才能再次配对。读取不创建缺失密钥。该机制不包含遗忘、清除或自动删除备份。

[原生连接决策](2026-09-25-native-remote-connection-source.zh.md)继续拥有 TLS、证明和 Gateway；本决策替换其单 Host 存储与恢复行为。[输入保存决策](2026-09-26-android-encrypted-input-checkpoints.zh.md)继续按 Host id、指纹和设备 id 隔离，因此替代授权即使替换同一目录项，也使用独立输入。两份决策继续有效。

## 考虑过的替代方案

**分别保存当前选择与凭据。** 独立写入可能恢复尚未提交授权的选择。一个加密文档只有一次原子替换。

**停止模型生产者之前发布目标。** 旧 UI 回调可能以新身份发送。模型退出和控件隐藏先于采纳；只有旧资源退出完成后，新代际才能使用。

**目录失败后自动恢复旧凭据。** 这会静默更换主体并掩盖损坏状态。显式导入仅限目录不存在；显式恢复保留不可读取字节。

## 后果

不同 Host 上同 id 的 Session 分别保留草稿、答案和待确认 prompt 身份。core 测试覆盖存储拒绝、加密、原子写入失败、提交前后取消、授权复用、主体隔离及退出失败。Android 场景配对两台真实 Host、切换已保存身份、重启并保留输入，且核验 prompt 只发送到当前 Host。损坏恢复在隔离验收应用内运行。物理设备、硬件密钥永久失效、突然断电及发布资格仍需单独验收。
