# Agent Note: Remote link access vertical slice (PoC-2)

Status: implemented

English | [中文](2026-08-30-remote-link-access-vertical-slice.zh.md)

## Problem

The all-platform nativization plan (E:\11585 plan, chapters 5–8, 20–29, 71–72) needs native companion clients to reach one Harness host over the network. The repository had no device identity, no pairing, no remote endpoint policy, and no TLS anywhere; the browser `/api` surface trusts a loopback fence plus an HMAC cookie, which is the wrong trust model for a phone on the LAN. The plan forbids solving this with a second business gateway, so the access layer had to dispatch onto the existing Typert gateway surface behind a new device-authenticated fence.

## Decision

Three packages under `packages/remote/` add the access layer. `dsh-device-trust` (`ctx.deviceTrust`) is a SQLite store owning a stable host identity, one-time pairing codes stored only as SHA-256 digests, and device records carrying an Ed25519 public key, a role (`observer`, `controller`, reserved `administrator`), timestamps, and revocation; pairing consume deletes the code row before inserting the device row, and both `DatabaseSync` calls are synchronous on the single host connection, so the consume is atomic. `dsh-link-access` (`ctx.linkAccess`) binds a TLS listener whose self-signed ECDSA P-256 certificate is assembled in-package as a fixed X.509 v3 template and identified to devices by the SHA-256 fingerprint of its SubjectPublicKeyInfo; every device request carries identity, timestamp, and an Ed25519 signature over `timestamp\nmethod\npath\nsha256(body)`, and authorization is an endpoint allowlist (invocation kind plus minimum role) resolved at load, with `$events/result` marked protocol-defined so the independent `allowRemoteApproval` switch applies regardless of which allowlist lists it. Unary RPC dispatches through `ctx.connection.createSharedFetchHandler('/api')` and streams pump `typertGateway.wireStream` as NDJSON — the same adapter pair `dsh-host-electron-ipc` uses, so the carrier adds a trust fence, not a protocol. `dsh-link-client` is the reference client: SPKI pinning happens in a custom `https.Agent.createConnection` on `secureConnect`, before any request byte is written, and a stream that closes without ending throws `carrier-lost` instead of ending quietly so callers resubscribe rather than treat silence as completion.

Wiring: `dsh-web-app` gains an inert `device-trust` row and a `link-access` row shipped `disabled: true` (remote access never opens by default; a deployment enables it with a patch overlay), `SERVICE_PAGE`/`LINK_MAP` classify the two services and six types to `docs/subsystems/remote-link(.zh).md`, and tsconfig aliases, `tsconfig.host.json` references, the host tsdown entry glob, and the package maps are updated. Replay protection is the clock-skew window only; per-nonce tracking waits for a benchmark, per the plan's no-premature-transport rule.

## Consequences

The PoC-2 reference sequence (pair → describe → call → stream → cursor-resumed reconnect → abort → dispose → pin mismatch → carrier teardown mid-stream) passes end-to-end against a real TLS socket, and the carrier tests cover pairing happy/replay/expired/malformed, all five 401 families, allowlist/kind/role/approval rejections, declared and streamed 413s, `$events` ready with a role-gated interaction answer behind the approval switch, client-vanish abort of an in-flight unary call and stream, certificate reuse across mounts, port conflict, and disabled-by-default — 48 tests, per-file 100% coverage on all three packages. Windows pairing UI, device manager, remote approval settings, and mDNS advertisement are deferred to the Phase 1 host UI increment on top of `ctx.linkAccess`; SessionController-level session e2e through the carrier is deferred to the first companion conformance suite (the carrier already exercises the same gateway dispatch chain the browser tests cover); Swift/Kotlin companions and shared golden fixtures are Phase 2 work against `dsh-link-client` as the executable contract.

## Alternatives considered

A second remote business gateway is banned by the plan and would duplicate controller ownership. `@peculiar/x509` for the certificate drags a tsyringe/`reflect-metadata` global polyfill into the host process; `selfsigned` uses a pure-JavaScript RSA keygen measured in seconds; the in-package fixed X.509 template over a node-generated P-256 key avoids both and stays a protocol constant. Reusing the browser cookie fence would copy the loopback trust model onto LAN traffic. The WebSocket mux was not extended to a second listener: NDJSON streams over `wireStream` already form the desktop carrier union, so the remote carrier reuses that shape with zero gateway changes.
