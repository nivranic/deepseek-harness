# Agent Note: Remote link access vertical slice (PoC-2)

Status: implemented

English | [中文](2026-08-30-remote-link-access-vertical-slice.zh.md)

## Problem

The all-platform nativization plan (E:\11585 plan, chapters 5–8, 20–29, 71–72) needs native companion clients to reach one Harness host over the network. The repository had no device identity, no pairing, no remote endpoint policy, and no TLS anywhere; the browser `/api` surface trusts a loopback fence plus an HMAC cookie, which is the wrong trust model for a phone on the LAN. The plan forbids solving this with a second business gateway, so the access layer had to dispatch onto the existing Typert gateway surface behind a new device-authenticated fence.

## Decision

Three packages under `packages/remote/` add the access layer. `dsh-device-trust` (`ctx.deviceTrust`) is a SQLite store owning a stable host identity, one-time pairing codes stored only as SHA-256 digests, and device records carrying an Ed25519 public key, a role (`observer`, `controller`, reserved `administrator`), separately branded Session and Workspace grants, timestamps, and revocation. It opens the database and loads `node:sqlite` only when an operation first needs persisted state, so module import, configuration inspection, CLI help, and disposal without use do not activate SQLite. Pairing uses one `BEGIN IMMEDIATE` transaction to burn the code and insert the device plus grant rows; another consumer cannot interleave, and a device cannot commit without its intended grants. Schema version 2 rejects the unreleased version 1 layout under the repository's pre-release format policy. `dsh-link-access` (`ctx.linkAccess`) binds a TLS listener whose self-signed ECDSA P-256 certificate is assembled in-package as a fixed X.509 v3 template and identified to devices by the SHA-256 fingerprint of its SubjectPublicKeyInfo. Serial generation rejects samples that would encode as zero after clearing the sign bit, which keeps the DER integer positive and minimal. A persisted certificate that Node rejects causes the key and certificate to regenerate together; its changed fingerprint requires affected devices to pair again. Every device request carries identity, timestamp, and an Ed25519 signature over `timestamp\nmethod\npath\nsha256(body)`. Its load-time endpoint table fixes invocation kind, minimum role, and resource policy for every product endpoint; product scopes cannot be overridden, and custom endpoints must opt into `unscoped` explicitly.

The carrier checks top-level Session and Workspace grants before dispatch and projects Host-wide Session, Workspace, and event collections before socket output. Existing Session, Workspace, Artifact, Attachment, and filesystem owners still validate their business relationships after the top-level grant passes. `session/handoff` remains unscoped because its input creates a new Full Session and names no existing Session resource. Remote interaction answers require a controller, `allowRemoteApproval`, the authenticated device's Host-issued Client generation, a delivery the Gateway still owns as pending, and the interaction Session grant. The Gateway exposes only pending-delivery query and `next` delegation on its in-process wire adapter; it remains the sole pending-event registry, while filtered, disabled, revoked, and stopped Link generations delegate instead of stranding the Host waterfall. Unary RPC dispatches through `ctx.connection.createSharedFetchHandler('/api')` and streams pump `typertGateway.wireStream` as NDJSON — the same adapter pair `dsh-host-electron-ipc` uses, so the carrier adds a trust fence, not a second protocol or business Gateway. `dsh-link-client` is the reference client: SPKI pinning happens in a custom `https.Agent.createConnection` on `secureConnect`, before any request byte is written, and a stream that closes without ending throws `carrier-lost` instead of ending quietly so callers resubscribe rather than treat silence as completion.

Wiring: `dsh-web-app` gains an inert `device-trust` row and a `link-access` row shipped `disabled: true` (remote access never opens by default; a deployment enables it with a patch overlay), `SERVICE_PAGE`/`LINK_MAP` classify the services and public types to `docs/subsystems/remote-link(.zh).md`, and tsconfig aliases, `tsconfig.host.json` references, the host tsdown entry glob, and the package maps are updated. Pairing grants default to all Sessions and Workspaces to preserve the explicit single-user pairing flow; a deployment can narrow newly paired devices with `pairingAccess`, while changing an existing device means revoke and re-pair. Replay protection is the clock-skew window only; per-nonce tracking waits for a benchmark, per the plan's no-premature-transport rule.

## Consequences

The real-TLS carrier and built Host composition cover selective grants, pre-owner denials for Session, Attachment, and Workspace paths, pre-socket Session and Workspace projection, Host-issued interaction correlation, pending checks, observer and approval-switch denial, safe retry after dispatch failure, revocation, and carrier shutdown. Direct authorization tests reject malformed envelopes and frames and cover every Session address, collection baseline, incremental frame, Remote notification, waterfall, and cancellation branch; `dsh-device-trust`, `dsh-link-access`, and the Gateway retain per-file 100% coverage. A disconnected Client generation leaves pending interactions in the Gateway for reconnect replay; an explicit policy change, revocation, or carrier stop delegates deliveries immediately. Grant administration UI and mDNS advertisement remain deferred product work; the resource grant tables and `pairingAccess` configuration provide the security behavior without creating complex RBAC.

## Alternatives considered

A second remote business gateway is banned by the plan and would duplicate controller ownership. A separate approval registry would race the Gateway and make first-valid-answer semantics impossible to prove, so the carrier uses the Gateway's pending query and delegation operations instead. `@peculiar/x509` for the certificate drags a tsyringe/`reflect-metadata` global polyfill into the host process; `selfsigned` uses a pure-JavaScript RSA keygen measured in seconds; the in-package fixed X.509 template over a node-generated P-256 key avoids both and stays a protocol constant. Reusing the browser cookie fence would copy the loopback trust model onto LAN traffic. The WebSocket mux was not extended to a second listener: NDJSON streams over `wireStream` already form the desktop carrier union, so the remote carrier reuses that transport and adds only the two pending-delivery operations needed to preserve Gateway ownership.
