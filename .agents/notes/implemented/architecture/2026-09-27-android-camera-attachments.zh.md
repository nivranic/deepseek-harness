# Agent Note: Android 相机输出只携带临时文件授权，不恢复上传授权

Status: implemented

[English](2026-09-27-android-camera-attachments.md) | 中文

## 问题

系统相机把完整尺寸的拍照结果写入调用方提供的输出 URI。因此，其他应用处于前台时，伴随端仍拥有临时文件及写入授权。迟到结果、上传取消或进程退出不能让该授权无限期保留，不能把照片附加到另一个 Session，也不能在没有新显式选择时恢复上传权限。相机结果缩略图不等于完整照片。

## 决策

相机入口使用 AndroidX `TakePicture`，提供显式输出 URI，并通过 intent 与 `ClipData` 携带读写授权。伴随端不请求 `CAMERA` 或广泛媒体库权限，拍摄由所选相机应用负责。其 `FileProvider` 不导出，只通过 `${applicationId}.native-camera` 授权访问 `cache/native-camera/captures/`。每次分配在该目录创建一个 `capture-<UUID>.jpg`。成功的 Boolean 回调只允许读取该次输出；返回 intent 的数据和缩略图不提供附件字节。

[照片决定](2026-09-27-android-photo-attachments.zh.md)拥有图片暂存、规范化元数据、完整混合附件意图及共享限制。相机复用 `image-upload.stage.v1` 能力、核心图片准入和 `fileUploads/uploadImage` 操作。完整尺寸 JPEG 遵守既有 512 KiB 源大小限制；Android 不会静默重新压缩过大的拍摄结果。相机确认会把图片暂存到草稿；prompt 提交仍需显式操作。不新增 Host 操作、Session 事件或加密输入格式。

Activity 持有的选择器跨旋转保留原始 Host 模型、Session 选择及拍摄授权。相机回调与文件、照片回调区分，但两种图片来源共用核心图片准入。共享附件占用在拍摄、读取、上传和取消清理期间阻止模型层发送与重试。Session 代次变化或 Host 退役后不能采纳迟到的相机结果。取消已启动的相机会把结果标记为丢弃。输出清理可能先完成，但选择器仍保留输出名称、已注册 launcher 和占用的回调位置，直到实际结果被消费。在此等待期间，不能开始新的文件、照片或相机选择。启动前取消则在清理后释放选择器。

## 临时输出生命周期

`NativeCameraFiles` 是进程单例；活动输出读取要求准确的内存租约令牌。拍摄分配与最终释放共享占用，避免取消遗漏正在分配的文件。成功入口保留输出，直到所属读取/上传任务结束，再撤销准确 URI 授权并移除该文件。取消、启动失败、无效结果和持有者退役也会释放所属输出。本地清理不会回滚 Host 已存储的不可变图片字节。

`SavedStateHandle` 只保留输出文件名和 `native-camera-awaiting-result` 状态，供清理与丢弃结果使用，不恢复模型、租约令牌或上传授权。若仍有待返回回调，恢复的 launcher 会消费并丢弃它，无论它先于还是晚于清理到达。若进程退出前已消费回调，恢复只执行清理，不等待另一个结果。两种情况都不会重新打开相机。

冷进程首次使用存储时，先撤销专属目录内未持有租约的 UUID 命名拍摄文件的 URI 授权，再删除它们。旋转复用已有进程存储，保留活动租约。清理要求目录准确对应应用缓存下的规范拍摄路径，拒绝符号链接，不修改无关名称。[文件决定](2026-09-27-android-file-attachments.zh.md)的源文档规则仍然独立：应用拥有这些相机输出，可以删除它们，而用户选择的文档保持不变。URI 撤权无法强制关闭外部相机已经持有的文件描述符。

核心在不可取消的清理结束前报告 `CLEANING`。清理失败产生携带 `CLEANUP_FAILED` 的 `FAILED` 状态，并显示固定本地化提示；清理元数据保留供后续恢复尝试。即使清理失败，核心也会释放提交占用。待返回的相机结果丢弃后，后续附件操作可以继续，清理失败仍保持可见。

已完成的图片回执遵循[加密输入持久化](2026-09-26-android-encrypted-input-checkpoints.zh.md)。Android 进程重启后，它以相同有序草稿和请求身份恢复，不重新读取拍摄文件、不重新打开相机、不再次上传，也不自动发送。未完成的拍摄不恢复附件。Host 回执过期仍使用既有显式丢弃并重新选择的恢复路径。

## 考虑过的替代方案

**使用返回的缩略图。** 缩略图可能缺失，也可能远小于相机 JPEG。显式输出 URI 提供单个完整尺寸来源，可独立核对其字节。

**把拍摄结果发布到 MediaStore，或申请广泛的相机/媒体访问。** 伴随端只需要单个临时输入，不需要拥有用户照片库或内嵌相机。仅授权私有输出，避免新增永久媒体条目及更广泛的权限状态。

**保存拍摄 URI，并在进程退出后继续上传。** 清理元数据不能证明当前上传意图，也不能确定当前 Host/Session 持有者。已完成回执通过输入存储恢复；未完成拍摄直接退役，不上传。

**文件清理完成就注销相机 launcher。** 外部结果可能晚些到达，并在缺少回调时滞留于 Activity Result 保存状态。保留已注册 launcher，直到消费并丢弃该结果，才能在准入下一次选择前结束已启动请求。

**相机返回后立即删除输出。** 附件读取和上传仍拥有源文件。清理等待其任务结束，使取消和正常完成遵循相同生命周期规则。

## 后果

伴随端增加相机入口，同时保留既有 Host 图片与 prompt 机制。完整尺寸照片可能超过移动端有界入口限制，阻塞的提供方可能延长等待清理。物理设备、第三方相机应用、后台拍摄、自动续传及真实模型图片理解需要独立验收。

完整 Android core 结果记录 64 个套件、390 个测试通过，无失败、错误或跳过。应用与 instrumentation APK 构建通过。Android 34 模拟器上的已安装文件/照片选择器与[相机测试](../../../../apps/android/app/src/androidTest/kotlin/ai/deepseek/dsh/companion/NativeCameraCaptureTest.kt)共 18 个用例全部通过，其中 9 个为相机用例。这些检查覆盖应用所持输出与 Activity Result 生命周期行为。

[相机场景](../../../../apps/web/tests/android-camera-attachments.e2e.ts)使用 Android 34 x86_64 模拟器上的真实系统相机通过，两个已安装 APK 的哈希均匹配当前构建。独立读取的 1392 × 1856 临时 JPEG 与上传字节一致。Host 保存的规范化字节与附件 id、字节数匹配；Android 独立解码核对其尺寸与媒体类型。源图片与规范化图片不必具有相同哈希。

取消拍摄保留完整草稿、删除临时输出，且不调用 Host。上传完成在 Host 操作结束后清理来源。第二次拍摄待返回时实际终止进程，恢复后保留相同的已完成回执、草稿和请求身份，移除孤立输出，不上传或发送 prompt。显式提交准确记录一条包含预期 `ImageBlock` 的用户来源消息；Session 授权读取返回独立计算过哈希的已存字节。模型响应来自无密钥录制 fixture。

最终原生回归分两次运行通过：7 个文件的 8 个用例覆盖相机、照片、文件、输入持久化、两个丢确认恢复用例、诊断和查看位置；独立的[持久下载运行](../../../../apps/web/tests/android-download-adoption.e2e.ts)通过 1 个文件的 1 个用例。两次运行合计在所测模拟器上覆盖 8 个文件、9 个用例。
