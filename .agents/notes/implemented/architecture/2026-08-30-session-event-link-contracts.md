# Agent Note: Session-event vocabulary in dsh-link-contracts

Status: implemented

English | [中文](2026-08-30-session-event-link-contracts.zh.md)

## Problem

CompanionUI's timeline folded follow records with a generic recursive text probe, its tests fed invented frame shapes, and the plan/todo/goal pane's production source was deliberately empty — all three waiting on the session-event contract models the previous CompanionUI note named as the natural next increment. The real record vocabulary (SessionEventEntry envelopes and packed chunk-row runs inside follow snapshots) and the merge-extensible `SessionEventMap` payload shapes lived only in TypeScript, so a native companion had nothing executable to decode against.

## Decision

The contract table in `dsh-link-contracts` grew a closed, companion-rendered session-event subset. `LinkSessionEventKind` enumerates the 13 rendered tags (turn/step spans, user and assistant messages and chunks, tool calls and results, plan/todo/goal state, the seed marker) and `LinkChunkRowKind` the packed history rows; every tag except the payload-less `session/end-seed` has a payload row carrying `sessionEvents`/`chunkRows` metadata the manifest now exposes. Payloads are projection views, not lossless mirrors: `LinkContentBlock` keeps the `type` discriminator plus the display fields (text, toolCallId, isError, nested content), `LinkMessageSource` flattens the merge-extensible source kinds' display fields, and `LinkTurnEndReason` carries only the reason kind — variant fields beyond the modeled set are ignored by the generated decoders and unknown tags stay wire-valid, both documented in the README. Every event fixture satisfies the real `SessionEventMap` member, with the plugin merges pulled into the program through type-only edges on `dsh-plan-mode`, `dsh-tool-todo/types`, and `dsh-goal`; branded ids are built with the `dsh-llm/brand` constructors, and the goal id is a local cast because its constructor sits behind the heavy goal package root. Table field kinds were generalized for the new shapes: the `role` special case folded into generic `enum` references, `object-array`/`string-array`/`number-array` joined the union, `camel()` now joins `/` segments so slash-bearing tags form valid case names, and Kotlin enum entries emit upper-snake. The emitter validates that references resolve to rows of the matching shape and that claimed tags are values of the vocabulary enums — mis-naming fails generation, not just review. CompanionUI consumes the generated structs through a `ContractCodec` bridge (JSONSerialization over the passthrough `WireValue`), `RemoteSessionViewModel` folds the real `{type: "event"|"chunks", event: {…}}` envelopes with per-kind Chinese summaries, and the same fold maintains the plan/todo/goal pane state last-write-wins (`plan/mode` is a boolean — the pane's planSteps list narrowed to what the wire carries). The pane view reads the `@Observable` model directly; the interim `PlanTodoGoalSourcing` abstraction, whose production source was empty by design, is gone.

## Consequences

Thirteen new fixtures ride the existing drift pipeline: a host-side change to any modeled payload fails the link-contracts typecheck first (the `satisfies` pins), then the manifest/Swift/Kotlin drift gate until artifacts regenerate, and the synced `apps/apple` copies carry the same bytes the Swift fixture-replay tests will decode on a macOS lane. The view-model tests now feed real envelope shapes — turn start, a packed text-chunks row, plan mode, an assembled assistant message with usage, a whole-list todo write, and a goal create — and assert both the per-kind timeline summaries and the pane fold, including the goal-clear tombstone; the fixture-replay suite round-trips every new fixture through the generated models and checks the wire-tag enums. Swift is still authored-not-compiled on this host (same macOS-lane caveat as the core and UI layers): correctness rides the TypeScript-side pins, the byte-for-byte drift gate, and the fixture JSONs. Unknown event tags render as marker rows through the generic path, so the closed subset can grow one tag at a time without a wire change.

## Alternatives considered

Mirroring the full merge-extensible `SessionEventMap` (request headers, compaction records, model selection, titles) was rejected: the companion renders a subset, unknown tags must stay wire-valid regardless, and modeling `EpochHeader`/`LlmCallConfig` would balloon the table for no rendered pixel. Hand-writing a Swift event enum was rejected — guessed wire shapes are exactly what the contract pipeline exists to prevent. Keeping the pane's sourcing protocol was rejected once the production source existed: reading the observable model gives live pane updates, while a snapshot-loading indirection would only re-fire on session changes.
