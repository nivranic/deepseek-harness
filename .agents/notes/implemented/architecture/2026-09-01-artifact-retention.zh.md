# Agent Note: 工件字节保留

Status: implemented

[English](2026-09-01-artifact-retention.md) | 中文

## 问题

已存工件字节永久存在：`DSH_HOME/artifacts` 无界增长，工件 README 把它列为已知限制。本产品的会话从不删除（持久化缝没有 delete 面；`session/disposed` 是只观察的内存事件），因此不存在可以挂垃圾回收的“引用消失”触发点。

## 决策

保留是本地后端上的可选年龄窗口。`LocalArtifactStore` 增加 `retentionDays` 配置字段——工件可老化的正整数天数，插件加载时校验（坏值响亮失败）；省略则永久保留每件工件，与“用户保留的一等输出文件”契约一致。配置后，构造器注册一次 boot 清扫加每日周期：`sweep(retentionDays)` 遍历 `artifacts/`、stat 每个 `<id>.artifact` 文件、删除字节老化越过窗口的文件并返回被删的 id。年龄是字节写入以来的时间——读取从不刷新它——清扫逐文件尽力而为，读不了的条目记日志跳过。日志引用比被清字节活得更久不是新失败模式：线上的 `ARTIFACT_CONTENT_MISSING` 与 `artifact_read` 的响亮未存错误早已建模它。

`ArtifactStore` 缝保持 put/get/remove——保留是本地后端自有文件上的提供方策略，内存或远程后端可能永远不想要它。引用感知回收（只删除无会话日志引用者）有意未建：没有会话删除它今天收不走任何东西，也止不住限制所名的无界增长。

## 后果

部署可用一行 cordis.yml 约束工件磁盘占用；默认组合逐字节不变。清扫节奏（boot 加每日，unref 计时器）固定——只有窗口可配置。按年龄删除可能删掉长命会话仍引用的工件；该读取按设计响亮失败，工件的日志行（类别、标题、格式、状态）比字节活得更久。相邻的延续延期：内容寻址去重（相同字节仍存两份）。

## 考虑过的替代方案

默认开启保留被否决——N 天后静默删除用户文件与工件契约矛盾；默认关闭让出厂行为完全一致。引用感知清扫被否决——今天空洞（没有会话删除产生引用消失）且对增长无效。读取刷新年龄（按访问驱逐）被否决——工件是被保留的文件而非缓存，在 `get` 里刷 mtime 会让保留行为依赖日志解释不了的读取模式。
