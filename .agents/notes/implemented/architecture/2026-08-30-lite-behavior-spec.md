# Agent Note: Lite Behavior Spec — Phase 3 foundation

Status: implemented

English | [中文](2026-08-30-lite-behavior-spec.zh.md)

## Problem

Phase 3 (Native Harness Lite) needs its consistency substrate before any Swift or Kotlin runtime exists: plan chapter 33 fixes the mechanism (Contract + Lite Behavior Spec + Golden Fixtures + Conformance Tests) and chapter 63 the verification points (Prompt, Streaming, Cancel, Tool Call, Tool Result, Plan, Todo, Artifact, Provider Error, Network Error, Handoff Request), with chapter 34's P0 capability list bounding the vocabulary and chapter 35's `requiresFullRuntime` marking what a Lite runtime must hand off instead of serving.

## Decision

The spec lives in `dsh-link-contracts` beside the domain-state conformance it already owns (chapter 61's extend-the-existing-owner rule; the package is the cross-language drift machinery's home). `src/lite-spec.ts` defines the Lite lifecycle event vocabulary — seventeen flat event shapes covering prompt accept/reject, stream deltas and reasoning, message completion with usage, turn completion/cancellation, tool call/result pairing, plan and whole-list todo changes, artifact reference/status (metadata only, per chapter 56's rule that large content never rides event streams), provider and network errors, and handoff requests — plus `foldLiteDomain`, the TypeScript reference fold into the Lite domain state (conversation rows, streaming partials, interrupted flag, paired tool trajectory, plan/todo, artifact references, terminal turn outcome, failures, pending handoff). Six keyless golden scenarios cover all eleven chapter-63 points; `generateLiteConformance` pairs each event sequence with the derived expected state, and the existing gen/verify pipeline emits `generated/lite-conformance/<id>.json` plus synced Apple copies under the same byte drift gate.

## Consequences

A native Lite runtime's conformance test is now a plain decode-fold-compare against committed bytes: replay the events, fold them, match the expected state — the same shape as the companion domain-state conformance, so the eventual Swift Lite runtime reuses the harness pattern wholesale. Behavioral choices the fold pins deliberately: a cancel finalizes the delivered stream prefix as an interrupted assistant row; a network drop stops the stream but keeps the partial for resume; a provider error clears streaming and sets the terminal outcome; artifact content never appears, only references. The unit suite asserts scenario semantics (including coverage of every chapter-63 point) and artifact self-consistency; the drift gate fails until regenerated bytes are committed. The spec is vocabulary-first: no runtime, transport, or provider adapter exists yet — those are Phase 3's next increments (Swift Lite loop skeleton against the mock-provider scenario replay).

## Alternatives considered

A dedicated `packages/lite/*` package was rejected for now — the spec has no runtime code yet, and the drift machinery (emitter, gate, Apple sync) is exactly what `dsh-link-contracts` owns; splitting later is a rename away. Deferring the spec until the Swift runtime exists was rejected — chapter 33 names the spec as the mechanism that keeps implementations behavior-compatible, and it is cheapest to write before any implementation biases it. Modeling Lite events as session events (reusing `SessionEventMap`) was rejected — Lite is a native lightweight runtime with its own vocabulary (chapter 33: not a full Node harness port); cross-compatibility is a projection concern for later, not a shared type.
