# Agent Note: Android 下载检查点将加密分段绑定到单一主体和资源

Status: implemented

[English](2026-09-27-android-download-checkpoints.md) | 中文

## 问题

有界预览不能保留大文件。进程丢失后继续部分下载还需要核对所选 Host 授权、Session、文件版本和已接受字节，仅记录偏移量不足以恢复。在字节持久化前保存新偏移量会遗漏数据；接受未提交尾部则可能混入失败写入。

## 决定

`FileNativeDownloadStore` 在应用私有目录中以独占文件系统锁持有单个传输。加密检查点绑定 Host 标识、固定指纹、设备授权、Session 和请求路径。每个经过认证的加密分段绑定随机传输标识、序号、字节偏移和 EOF。调用方提供带认证的加密器、单窗口限制和总内容限制。校验与复制的明文内存均与单窗口成比例；总内容限制不包含加密和分帧开销。

追加先同步分段，再原子替换已经同步的加密检查点。恢复校验所有已提交分段，忽略其后的字节。显式追加仅截断未提交尾部。元数据或已提交分段损坏时保留原文件并停止续传。检查点替换失败时，前一个前缀仍为权威。完整传输必须收到已接受的 EOF，空文件也不例外。完整复制可能在写出前几个窗口后失败，因此消费方必须丢弃不完整目标。

`NativeDownloadController` 恢复本地状态时不发送网络请求。显式续传先重新核对完整描述，再读取缺失后缀。每个窗口与有界资源预览共用解析器；版本、路径、大小变化，以及偏移错误、base64 格式错误和矛盾 EOF 均不能拼接进已有前缀。退役取消并等待网络和磁盘工作，再释放独占锁。调用方必须先退役此控制器，再采纳另一个 Host。

应用使用 Android Keystore 加密构造此设施，并将完整磁盘内容接入文档选择器。[应用接入决定](2026-09-27-android-persistent-download-adoption.zh.md)拥有模型退役、缓存配额、下载控件及显式本地移除；本决定继续拥有持久格式与恢复规则。[资源读取决定](2026-09-27-android-current-resource-reading.zh.md)、[完整快照保存](2026-09-27-android-complete-resource-save.zh.md)及[保存 Host 的所有权](2026-09-26-android-saved-host-catalog.zh.md)继续有效，分别约束呈现、结果生命周期和身份采纳。

## 考虑过的替代方案

**在内存中保留所有窗口。** 文件大小会决定堆占用，进程丢失也会丢失进度。

**使用明文缓存或只保存偏移量。** 明文缓存会使资源内容脱离认证存储策略；偏移量不能证明字节所属主体或版本。

**仅追加独立日志而不保存检查点。** 末尾分段截断时无法可靠地区分追加中断与已提交内容损坏。独立原子检查点准确界定必须校验的分段。

**恢复凭据后自动续传。** 恢复身份不等于恢复用户的传输授权。显式继续使进程恢复与网络意图分离。

## 后果

核心测试使用真实加密文件，覆盖跨主体和 Session 密文移植、描述变化、损坏、有界复制、重试、暂停及等待退役。独立 JVM 在同步分段后、替换检查点前突然退出；重新打开验证旧前缀，释放死亡进程的独占锁，并替换未提交尾部。该核心证据限定本地 JVM 进程中断；应用接入决定拥有 Android 进程与文档提供方证据。密钥缺失、原子移动不受支持及磁盘错误均失败，不降级为明文。不提供自动存储淘汰与后台调度。断电持久性、防回滚存储、硬件故障、物理设备与第三方文档提供方资格尚未建立。
