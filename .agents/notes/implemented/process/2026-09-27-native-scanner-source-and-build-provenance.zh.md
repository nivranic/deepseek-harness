# Agent Note: 原生扫描器验证拥有已提交源码与显式构建输入

Status: implemented

[English](2026-09-27-native-scanner-source-and-build-provenance.md) | 中文

## 问题

Android AAR 即使带有已核验的历史回执，也不能证明可从当前候选源码复现构建。缺少扫描器与构建器源码，还会妨碍与应用一起审查准入实现和执行拒绝测试。只存在于宿主的子进程改写会隐藏构建实际采用的校验和策略。

## 决策

[共享 Go 扫描器](../../../../native/support-scanner/README.zh.md)与 Android 构建器的依赖闭包位于本仓库。Gitleaks 继续作为维护中的规则引擎；应用导出器保留字段选择、身份与交付所有权。不引入第二套 Host 支持包生产者或 runtime 服务。扫描器的 canary、不可变获准字节、固定拒绝和等待取消语义保持不变。

`test:support-scanner` 执行门禁自身拒绝控制、Python 源码/构建/产物测试、Go 模块核验、行为测试和 vet。它要求策略指定的编译器以及非空的已执行测试集，并显式报告跳过项。门禁清除替换模块/workspace 的设置，强制验证公共校验数据库。它不能替代竞态分析、可达依赖漏洞检查或原生设备执行。

构建器只读取已提交的常规扫描器文件和仓库许可证，生成确定性的私有 Go 模块代理。正在运行的构建器文件必须与所指定提交一致。下载的私有模块必须与已提交文件清单及字节相符；外部模块继续验证校验和。Android 产物准入在记录成功前检查两个声明的 ABI、16 KiB ELF 对齐、JNI/R8 条目、源码与模块身份、私有路径排除及许可证。

显式的不含凭据的 HTTPS 模块代理可替换公共下载端点，而不关闭 `sum.golang.org` 或绕过私有源码核验。无效代理输入在创建工作目录前即失败。缓存、工作和输出目录保持独立，已有产物从不覆盖。[历史宿主适配记录](2026-09-20-scanner-toolchain-host-accommodations.zh.md)仍解释外部 AAR 的出处，但不是新构建器的执行策略。

由于构建器要求已提交输入，源码采用和产物验收是独立里程碑。恢复源码并通过测试，不能将应用已有的外部 AAR 重新标记为当前候选构建。后续构建必须指定实际源码提交并保留自己的回执；已安装准入与应用验收需要另外匹配的证据。

## 考虑过的替代方案

**只保留历史 AAR 与回执。** 这能保留产物，却把实现与编译输入留在候选源码之外。源码和拒绝测试需要与消费方处于相同审查所有权下。

**运行时改写子进程环境或关闭校验和验证。** 隐藏改写使已提交构建器无法完整描述执行。显式 HTTPS 代理保留公共校验数据库验证，并可通过无效输入测试核验。

**用旧提交 id 构建未提交源码。** 这会使回执中的源码身份失真。构建器拒绝已修改文件，因此必须先提交恢复的源码，再据此生成产物。

## 后果

Python 测试验证构建器文件被修改、无效版本、源码/缓存字节变化、归档路径别名、JNI/ELF 元数据及输出路径保留。Go 测试覆盖环境和行内允许配置下的真实秘密拒绝、不可变准入、取消、超时、panic 包含及并发扫描。门禁控制拒绝缺失测试所有者、不同编译器、空测试输出和全部跳过的 Python 测试。Windows 目录符号链接覆盖仍显式跳过；竞态分析、当前提交 AAR 构建、漏洞验收、Apple 绑定和物理设备仍需独立证据。

本机候选记录将不可变构建回执与已安装执行分开。独立检查重建已提交源码材料，对照两个二进制模块图及许可证哈希，并将应用 manifest 身份与已安装 APK、JNI 库和规则摘要匹配。重复构建在不同工作目录间比较 AAR 与回执字节，同时明确保留共享依赖缓存。二进制漏洞记录保留仅模块级提示及数据库身份；受影响包或符号命中会拒绝该项核验。这些观察不能证明干净机器、跨平台或发布资格。
