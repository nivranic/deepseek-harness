# Agent Note: 候选字节与未签名生产者证据

Status: implemented

[English](2026-09-06-candidate-artifact-integrity.md) | 中文

## Problem

构建成功或清单内部一致，仍可能描述错误源码、遗漏平台，或保留其他字节的校验值。未签名 provenance 也无法确认生产者身份。把元数据解析当作产物验收会隐藏这些不同的失败。

## Decision

[候选验证器](../../../../docs/development/release-candidate.zh.md)区分完整候选验收与单个平台验证。独立选定的源码和 checkout 所属产品标识约束每份回执。每个产物及证据文件都经过校验值验证；检查和 SLSA provenance 绑定相同交付文件，官方 CycloneDX 库校验 SBOM schema。合成夹具用于证明验证器行为，不代表平台构建。

调用方在验证和后续使用期间负责维持独占、无写入的产物目录。流式文件描述符、链接拒绝和重复元数据检查用于发现已观察到的变动，不宣称提供可移植文件系统沙箱。证据不被执行。保持文件不可变，才能避免把特定时刻的校验结果当成对后续替换字节的保证。

重试保留源码、标识和完整交付记录，同时允许刷新证据与执行元数据。这实现了[产品发布标识](2026-09-05-product-release-identity.zh.md)对不变重试和新分发的区分。分发变化时使用现有单调构建号规则。[候选安全扫描](2026-09-05-candidate-security-scans.zh.md)继续独立负责源码分析与信息披露决策。

## Alternatives considered

- 要求整份清单完全相同，会把重新扫描或 provenance 执行标识更新当作新的应用字节。
- 只检查 JSON 引用，会让被修改的文件或其他源码的证据继承 PASS。
- 手写 SBOM 子集可能接受无效的嵌套标准字段；标准验证由持续维护的 schema 库负责。
- 可移植未签名 provenance 无需托管认证服务即可使用，但不能认证构建者。签名证明需要独立的可信生产者。

## Consequences

验证增加了仅用于开发的 schema 依赖，并要求 ASCII 产物引用、普通文件和已完成写入的目录。Full 与 companion 标签用于区分分发职责，不证明原生 Lite 行为。扫描器执行、打包清单完整性、安装、GUI 就绪、生产签名和真实四平台装配都需要验证器之外的平台证据。

聚焦回归覆盖混合标识、不完整平台、路径别名、链接、文件缺失或字节变化、虚假 PASS 检查、无效嵌套 SBOM 数据、被修改的 provenance subjects、独立源码预期和分发递增。CLI 子进程用例证明修改单字节或策略缺少平台后返回非零退出码。这些属于合成验证器测试，不是发布验收。
