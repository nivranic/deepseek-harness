# @deepseek-ai/dsh-android

English | [中文](README.zh.md)

The downstream thin Android companion for DeepSeek Harness. The device is a Remote Companion first: it never runs the agent runtime and holds no second session truth. This project starts with the contract module that consumes the shared Remote failure vocabulary; the `core` domain module and the `app` shell have now migrated onto this build from the historical Android application source.

## Use this project

The `contract` module is a Kotlin JVM library that mirrors the candidate's Remote failure contract:

- `RemoteFailureClass` and `RemoteFailureClasses.classify(code)` mirror `RemoteFailureClass`/`REMOTE_FAILURE_CLASSES` from `@deepseek-ai/dsh-typert-protocol`. Codes without shared semantics — including every future code from a newer Host — resolve to `UNKNOWN` and must stay presentable as opaque diagnostics. A class names what the Client may do next; it never grants capability, permission, retry policy, or protocol-version admission.
- `EnvelopeSchemaTest` validates real recorded HTTP payloads against [the Remote failure JSON Schema](../../packages/typert/protocol/remote-errors.schema.json), rejects malformed known-code details, and proves the Kotlin mirror equals the generated projection of the TypeScript authority.

The schema is copied into the test run straight from the protocol package, so the Kotlin column always validates the current candidate bytes. The classification projection regenerates with `node scripts/gen-remote-failure-classes-json.mjs` (after `pnpm run build:lib`); committed output is verified by the test, and drift fails the build.

The `core` module is the migrated pure-JVM domain: the Lite fold (loop, chat, stores, tool registry), the Link pairing/wire stack (Noise, signing, pinning, diagnostics), Handoff snapshots, support export, and push/relay clients. Its test classes run on the JVM with `gradlew :core:test` — no Android SDK needed. The `app` module carries the Compose surface (chat screen, notifications, Keystore cipher, support scanner glue); building it requires the support-scanner AAR chain described under Known Limitations.

Run the tests with the Gradle wrapper from this directory (`gradlew.bat :contract:test :core:test` on Windows, `./gradlew :contract:test :core:test` elsewhere); the first run downloads the Gradle distribution and dependencies.

The core's `gateway/NativeGatewayClient` implements the current pinned Native Remote protocol through `WireDriving`: operator-issued `dsh-native-pairing` version 1, Connection RPC with API 2, and one shared `/api/remote.mux` WebSocket. Each dispatch signs a fresh device admission; only redemption is unsigned. Pairing verifies the returned device key fingerprint, assigned role, and negotiated Host identity before saving credentials. Session writer versions are observed independently of API negotiation. Credentials carry `transportFormat: native-gateway-v1`; restoration refuses legacy Link identities without deleting them. Deployments supply timeouts and per-stream buffer limits; overflow fails the affected stream rather than dropping values.

The Host transport scenario is [android-gateway.e2e.ts](../web/tests/android-gateway.e2e.ts). Prepare its Kotlin driver with `gradlew.bat :core:nativeGatewayClasspath` (or `./gradlew :core:nativeGatewayClasspath`), then run the scenario through `vitest.web.config.ts` with `DSH_ANDROID_JAVA` pointing to Java 17. The driver receives ephemeral pairing data through stdin, never command arguments. It covers pinning, acknowledgement checks, permission refusals, concurrent streams, cancellation, revocation, restoration, and awaited close.

The application selects `NativeGatewayClient` and stores its Keystore-encrypted identity in `native-gateway-credentials.json`; `link-credentials.json` remains untouched. Questions carry their delivered interaction revision and structured option/custom answers. Files use the selected Session as their scope, request the root as `.` and retain one version across line-based pages. Failed replies retain the card for explicit retry. HTTP RPC closes each connection without automatic retries, avoiding reuse of a socket the Host retired while the user was answering; the mux remains persistent.

The recorded [companion scenario](../web/tests/android-companion-question.e2e.ts) exercises both JVM models and the installed Compose Activity. Its Host limits pages to 1000 lines, so the 1001-line UTF-8 file requires a second read. Build `:app:assembleDebug :app:assembleDebugAndroidTest -PdshNativeAcceptance` with the scanner inputs below and install both APKs to an emulator. `DSH_ANDROID_ADB` selects adb and `DSH_ANDROID_SERIAL` must name an emulator. The scenario resets only the separate `.nativeacceptance` application, drives pairing and Question answers over a temporary ADB socket, and checks displayed file text after tapping Load more. Physical devices are refused by this driver.

## Understand the implementation

Session drafts and Question answers share encrypted input storage isolated by Host id, pinned fingerprint, and device grant. Saved input and the last ordinary Session survive process restart; restoring them only opens observations. Explicit submissions remain model-owned and wait for a saved checkpoint. Failed prompts retain their original text and request id independently of newer edits. Acknowledgements and matching Host receipts clear only the accepted intent; closed or revised Questions retire obsolete answers. Save failure blocks submission and offers retry. Unreadable input remains intact until explicit backup-and-reset recovery. The [input persistence decision](../../.agents/notes/implemented/architecture/2026-09-26-android-encrypted-input-checkpoints.md) owns format and recovery semantics; the [recorded scenario](../web/tests/android-input-persistence.e2e.ts) exercises process restoration and damaged encrypted storage.

The [lost-acknowledgement scenario](../web/tests/android-prompt-retry.e2e.ts) kills Android after real Host admission while the response is held. Explicit retry uses the saved request identity; a logged receipt can instead clear the pending intent without another prompt call. Both preserve newer text across another process restart.

The Session pane loads older history explicitly and can copy or open a viewing position using the Web v1 grammar. Opening requires the currently selected trusted Host, retains unsent input, and reveals the durable anchor without creating a Session or submitting a prompt. Pages use the opening log cut and preserve concurrent live records; cancelled or stale responses cannot cross observations. Defaults are 50 messages per request and 8 MiB of retained serialized records, with visible failure and manual retry at a read or size limit. The [view-location decision](../../.agents/notes/implemented/architecture/2026-09-26-android-native-view-location.md) owns lifecycle and limits; the [native scenario](../web/tests/android-view-location.e2e.ts) checks an older anchor in an 88-turn Host Session and Web-compatible copied output.

The Session list displays loading, empty, and failed states. Refresh and retry are explicit reads; requests serialize, cancellation returns to idle, and failures retain the last successful rows plus a fixed diagnostic category and any Gateway refusal envelope. The [list recovery scenario](../web/tests/android-session-list.e2e.ts) disconnects only its Host port forward, restores it for a manual retry, and then revokes the device grant. Send and stop remain disabled until a Session is open.

The saved Host chooser displays the current Host and its endpoint. Adding another Host preserves existing entries; switching restores only the selected principal's input. Business controls stay hidden while old models retire and the catalog commits credentials with selection. Re-pairing the same Host key replaces its grant. The [catalog decision](../../.agents/notes/implemented/architecture/2026-09-26-android-saved-host-catalog.md) owns atomic adoption, cancellation, and failure semantics; the [two-Host scenario](../web/tests/android-host-roster.e2e.ts) verifies same-id Session isolation and selected-Host dispatch. Host tasks continue and old grants require operator revocation.

A missing catalog offers explicit import of the previous native credential file and preserves the original. It never imports legacy Link authorization or falls back after catalog failure. Malformed catalogs, tampered ciphertext, or a missing Keystore key preserve the file and require explicit backup/reset before new pairing. Reads never initialize missing keys. The [recovery scenario](../web/tests/android-credential-recovery.e2e.ts) modifies only isolated acceptance storage. Hardware-backed permanent key invalidation remains unqualified.

Within the same in-memory Session owner, reconnect sends the last retained sequence. A contiguous delta preserves older pages; an overlapping full window retains an identical prefix, while an uncovered cursor replaces it with the authoritative latest window. Snapshot headers must match the selected Session; contradictory records and byte-limit failures preserve the held view and stop automatic recovery. New models and process restarts open without a cursor. The [cursor scenario](../web/tests/android-cursor-resume.e2e.ts) verifies covered and uncovered logical stream interruptions against a real Host; physical network and foreground recovery remain unqualified.

Session, Workspace, and interaction observations reconnect only after transport failures or classified temporary Host failures. Revocation, permission, compatibility, unknown refusals, invalid responses, and certificate failures stop automatic recovery. The approval screen presents the refusal, keeps failed answers for explicit retry, and disables answers while no event client is ready. Recovery never replays a business mutation. The emulator scenario closes and stops the application, restores the encrypted identity in a different process without another grant, and then exercises the recorded Question and file pages.

## Model Experience

The companion displays Host-owned Session events and returns explicit human answers through the current Gateway. It does not execute a model locally or add a separate transcript. The keyless acceptance scenario replays recorded model output; it does not qualify a live provider.

## Known Limitations and Deferred Work

`:app:assembleDebug` is gated on `verifyScannerResources`: the support-scanner AAR must be built from `native/support-scanner` (Go + Android NDK via `scripts/build-mobile-support-scanner.py`) and passed through `DSH_ANDROID_SCANNER_DIRECTORY`/`DSH_ANDROID_SCANNER_SOURCE` with its receipt. This host built that chain (Go 1.27.1, NDK 30.0.16248370 through sdkmanager): the AAR's static verification is PASS with its receipt, `:app:assembleDebug` passes the gate, and the APK installs and launches on a local emulator AVD with `MainActivity` resumed and no crash (log and screenshot in `.artifacts/scanner-aar-*.log`). The unreachable sum/proxy endpoints were worked around by pre-seeding the module cache through the goproxy.cn mirror with a pre-seeded go.sum, `GOSUMDB=off` for child processes (content integrity stays enforced by the ziphash cache, `go mod verify`, and the builder's provenance asserts), and stripped linking for the gomobile tools (the 360 active-defense heuristic blocks the default gobind binary). The shell consumes the Gateway failure contract: refusals carry the failure envelope verbatim (code, message, structured details) out of unary results and stream failure frames, and presentation classifies every code through the shared `RemoteFailureClasses` mirror — known classes get class-level copy and a next action, codes outside the vocabulary stay opaque diagnostics (`GatewayFailurePresentation.kt`, covered by `GatewayFailurePresentationTest` and the envelope-preservation cases in `LinkClientTest`).

The [legacy Link fixture](support/link-fixture-host.mjs) remains a historical protocol test and cannot qualify the current application. The application bundles `org.conscrypt:conscrypt-android` when the platform lacks Ed25519 key generation. Actual Native Remote acceptance uses the shipped Host composition and an isolated Android emulator application; camera scanning, physical devices, release signing, and platform interoperability remain unqualified.

Artifact retrieval still contains the retired `session/artifact` call and requires migration. The dormant Lite Handoff helper is a historical runtime-transfer test and is not used by viewing-location Handoff. Native transport diagnostics do not populate the legacy Link diagnostic snapshot. Deep links, platform share routing, and Swift viewing-location adoption remain unqualified; passing native reads does not imply complete compatibility of every tab.
